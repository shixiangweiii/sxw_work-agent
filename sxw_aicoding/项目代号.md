# Atlas 项目代号说明

> 确定日期：2026-08-24  
> 正式代号：**Atlas**  
> 完整写法：**Project Atlas**

> **重要备注：Atlas 仅作为项目代号，用于项目识别和日常沟通。不修改目前的代码、工程目录、文件、仓库、包、模块、类型或其他现有命名。**

## 1. 代号结论

本项目正式采用 **Atlas** 作为项目代号。

**WorkAgent** 继续表示项目所属的产品类别和能力定位；**Atlas** 用于指代这个具体的个人项目。

> **Atlas is my personal Work Agent project.**

## 2. Atlas 的核心寓意

### 2.1 承载工作

Atlas 源自希腊神话中肩负天穹的阿特拉斯，天然具有“承载”的意象。

这与项目的 Work Agent 定位相呼应：它不只回答问题或给出建议，而是逐步承接用户的真实工作，在授权与安全边界内调用工具、处理异常、验证结果并交付产物。

### 2.2 建立工作世界的地图

Atlas 在英文中也表示“地图集”。一个成熟的 Work Agent 需要持续理解和组织用户的工作世界，其中包括：

- Workspace 与可访问的资源；
- Session、Context 与长期工作连续性；
- Tools、Skills、Capabilities 与权限边界；
- 任务的步骤、依赖、进度与异常路径；
- Artifacts、Trace、Eval 与可验证的执行证据。

因此，Atlas 不仅意味着“替用户承担工作”，也意味着“理解工作环境并在其中寻找可执行路径”。

### 2.3 从目标到结果

Atlas 面向的不是单次对话，而是真实任务的完整闭环：

```text
用户目标
    ↓
理解工作环境与边界
    ↓
选择路径并调用工具
    ↓
观察现实状态并处理异常
    ↓
验证结果并交付产物
```

这一寓意强调：模型生成了答案、Tool 返回了成功，都不自动等于工作已经完成。Atlas 要关注的是真实世界中的结果是否已经发生、是否经过验证、是否可以交付。

### 2.4 与项目长期演进匹配

Atlas 不绑定某个办公软件、具体 Case 或当前技术形态。它可以覆盖项目从生产级 Agent Harness、实验评测平台、真实任务执行器，到个人桌面 Work Agent 的长期演进。

如果项目未来由 Work Agent 继续向更长期、更个人化的 Agent 形态发展，Atlas 作为项目代号仍然成立。

## 3. 代号与产品定位的对应

| Atlas 的意象 | 项目定位 |
|---|---|
| 承载 | 承接用户目标和真实工作 |
| 地图 | 理解 Workspace、Context、Tools 和环境状态 |
| 导航 | 在不确定环境中选择并调整执行路径 |
| 长途 | 支持长任务、持久化、恢复与持续跟进 |
| 坐标 | 通过 Trace、Artifact 和 Eval 保留可观察、可复现的证据 |
| 责任 | 不止于调用工具，而是观察、验证并推动结果发生 |
