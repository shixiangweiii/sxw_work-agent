# ADR-0015：浏览器可在 CLI 入口显式放开给 GUI 操作

- 日期：2026-10-03
- 状态：已采纳（用户要求「用新实现的 GUI computer use 测试，不要用 Playwright MCP」）
- 修订：[ADR-0013](0013-本机-computer-use-图像进模型轨道与自建-Swift-助手.md) 的硬拒绝名单 —— 只动「浏览器」一类

## Problem

ADR-0013 把浏览器放进硬拒绝名单，理由有两条：网页任务应走 Playwright MCP（按页面结构操作，比点像素可靠）；
更要紧的是 **Atlas 的审批卡片就显示在浏览器里** —— 允许 GUI 点浏览器，模型就能点到自己的「批准」按钮。
用户明确要用 GUI computer use 操作本机 Google Chrome。

## Decision

新增 `--computer-allow-browsers`，**只在 CLI 入口**：

- 只解除「浏览器」这一类；终端、IDE、Agent 宿主、凭证与安全类**无论如何**仍是硬拒绝；
- 放开 ≠ 加白名单：浏览器仍须写进 `--computer-apps`，否则照样拒绝；
- **Web 入口不接受这个开关**（`npm run ui -- --computer-allow-browsers` 启动即失败）：那里的审批卡片
  就在浏览器里，放开浏览器正是第一条理由描述的自我审批；CLI 的审批在终端，终端仍是硬拒绝；
- TS（配置解析 ＋ 每次动作前）与 Swift 助手（投递前）两道都认这个开关；开关进工具 version 摘要，
  resume 时白名单语义变了会被点名；启动横幅红字说出这次让渡。

理由只对浏览器成立：其余几类被拒是因为「等同无沙箱的 shell」或「凭证」，与入口无关，不开口子。

## Consequences（代价，一条都不许假装没有）

1. 截图会带上浏览器里的页面、**标签页标题与书签栏**，发往模型端点（实测：用户的其他标签页、书签、登录头像都在图里）；
2. 浏览器里的登录态（邮箱、网银、公司系统……）在模型可点范围内；网页文字可能是提示注入；
3. 如果另有一个 Atlas 白盒界面开在同一个浏览器里，那里的审批按钮也在射程内（CLI 这次 Run 的审批不在那里，但别的 Run 的可能在）；
4. 一次误点就是真实后果，而浏览器里能触发的后果（发送、提交、付款）比计算器多得多。

## Eval Evidence

- `verify:computer` O 段（3 条）：不放开时 Chrome 启动即拒且指出出路、放开之后终端 / IDE / 密码管理器 / Agent 宿主仍拒；
  放开 ＋ 在白名单照常执行且第二道收到放开标记、放开但不在白名单照样拒；Web 入口拒绝该开关且服务没起来。
  两处注入（放开扩到所有类别、handler 不把开关传给驱动）各自翻红。
- 真桌面 × 真端点：`run_536c62856c99`（qwen3.8-flash，白名单只有 com.google.Chrome）——
  `cmd+t` 新标签、输入网址并**自己删掉了 Chrome 的历史补全**、回车、点 B 站主搜索框、输入「agent开发面试」、回车；
  结果页 `search.bilibili.com/all?keyword=agent开发面试…`，前三条与独立截图核对一致，模型还自行标出第三条是广告。
  没有登录、没有点视频、没有关标签页。事后独立截图核对过。
