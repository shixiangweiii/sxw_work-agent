# ADR-0017：可证明无外部副作用的云沙箱执行，自动放行

- 日期：2026-10-16
- 状态：已采纳
- 修订：[ADR-0016](0016-云沙箱执行走一次借用一台用完即销毁.md) 决定 5（「v1 照常逐次问」）；
  与 [ADR-0012](0012-审批与执行特权是两条正交的档位轴.md) 的决 3 自动放行规则同一处落地

## Problem

ADR-0016 把研究问题建起来了，但没有回答它：

> **当副作用的范围可以被机械地证明为「只有声明过的那几个文件」，EXECUTE 还需要逐次审批吗？**

`autoGrantVerdict` 的第一条是 `effectType === "EXECUTE" → 不放行`。那条规则写于阶段 3.5，
它的理由是**本机** shell 的副作用范围说不清：能碰 workspace、能碰 `$HOME`（UNRESTRICTED 档）、
能联网、崩在中途时「做没做」无从判断。

`cloud_shell` 在 `network="none"` 且 `inputs` 为空时，**这四条一条都不成立**。
而它仍然被那条按 `effectType` 一刀切的规则挡着 —— 于是 ADR-0012 那十几次点确认，
在最不需要人看的那一档上原样重演。

## Decision

`autoGrantVerdict` 增加一支：`cloud_shell` 的 EXECUTE，**同时满足三条**才放行。

```
① network 档位是 none —— 彻底断网（含 DNS），池子下发 deny-all 并经平台回显核对
② 没有数据外发        —— inputs 为空，没有任何本地文件离开本机
```

判定收敛在 `tools/cloud-sandbox` 的 `isProvablyContained(effect)` —— 与产出这些事实的
resolver 在一起，**只有一份**。`compose.ts` 只是调用它。

### 【定】这里**不查** outputs 的路径边界，而那不是遗漏

handler 在借沙箱**之前**就拒绝越界的 outputs（`TOOL_PATH_ESCAPE`），所以在自动放行这一层
再查一遍，在任何可观察量上都与不查相同 —— **一个永远不可能被单独触发的守卫是装饰**。
本仓的纪律是「每道闸门都要有能单独触发它的判据」（M4 那条：一条不准的 kills 比没有更糟）。
边界归 handler，这一层只回答「要不要人看」。

### 为什么这三条合起来等价于一次 workspace 内的写

| 本机 EXECUTE 说不清的 | 这一档下 |
|---|---|
| 能碰哪些文件 | 沙箱是全新的，只有命令自己造的东西；用完即销毁 |
| 能不能联网 | 不能，而且**不是 Atlas 自己说的** —— 读回平台回显核对过 |
| 有没有数据外发 | `inputs` 为空，没有任何本地文件上传 |
| 崩在中途做没做 | durable effect 恰好是取回来的 outputs，可观察（ADR-0016 的分支二） |

所以这次执行对**用户拥有的任何东西**的 durable effect，就是「往 workspace 写那几个文件」——
而后者按决 3 本来就自动放行。放行它不是放宽边界，是**承认边界已经窄到不需要人看**。

### 【定】两条是合取，而且各自都要有能单独触发它的判据

这是本仓栽过四次的地方（「判据落在守卫重叠区」）。两条里任一条单独失效都必须有判据会红：
开了网不放行、有 inputs 不放行。少了任何一个反向，
一个「cloud_shell 一律放行」的实现都能让其余判据全绿。

### 【定】仍然留下完整的审批事件对

放行走的是既有的 `autoGrant` 通道，所以 `ApprovalRequested` / `ApprovalDecided` 照常成对出现，
`decidedBy` 如实记 `AUTO_GRANT`。它进 Trace、进事件流、进界面 —— 与 ADR-0012
「直接 ALLOW 的话，一次写到 $HOME 的操作在事件流上与一次写到 workspace 内的操作长得一模一样」
是同一条理由。

### 【定】判定读的是 `resolvedEffect`，不是重新解析入参

`autoGrantVerdict` 拿到的是 `PreparedAction`。它必须从**已经解析好的 effect** 上读，
不能自己再 parse 一遍 `normalizedInput` —— 那会出现第二份解析，而两份解析分叉时
「审批面说断网、实际开着网」不会有任何征兆。所以 `CloudShellEffectResolver`
把判定需要的事实编进 `scope.value`（`cloud:net=…;in=N;out=M`），
`riskFacts` 里 `DATA_LEAVES_HOST` 的有无是同一事实的第二种形态。

## Consequences（代价，一条都不许假装没有）

1. **模型可以在无人看管下跑任意代码**，只要它断网、不上传。挡住它的只剩
   「池子真的下发了 deny-all」＋「平台回显核对」两道 —— 而这两道都在 ADR-0016 里，
   都有判据与真实云端复核。但它们是机器，不是人。
2. **仍然花钱**。放行之后模型会更频繁地用它，而 Atlas 没有成本轴
   （ADR-0016 代价③）。轮次与工具调用数是仅有的两道闸。
3. **outputs 会覆盖 workspace 里的同名文件**，而这一步不再问人。与 `write_file`
   自动放行同级 —— 那条规则接受的正是这个代价。
   ⚠️ 差别要说出口：`write_file` 的内容是模型**直接写出来的**，而这里是
   **一段任意代码跑出来的**。两者在「能不能找回来」上同级，在「人能不能预读内容」上不同级。
4. **这一档下「人看过命令」不再成立**。事后归因只能靠 Trace 里的命令原文与
   `decidedBy: AUTO_GRANT`，不能再假设有人读过它。
5. **`network` 认不出来一律按 `none`**（ADR-0016 的保守解析）。于是一个拼错的档位名
   会落进自动放行范围 —— 但它同时也真的断网，所以边界没有被放宽，只是模型
   会以为自己开了网而命令失败。

## 实测之后才知道的那件事：这条规则覆盖面很窄

真实端点 ＋ 真实云沙箱的两次 live 跑（`--approval default`，**非 TTY**，所以没放行就等于被拒）：

| 任务 | effect | 结果 |
|---|---|---|
| 「算 sales.csv 的 amount 总和」 | `cloud:net=none;in=1;out=1` | **没放行** → 非交互下被拒。因为要上传 sales.csv，`in=1` 即数据外发 |
| 「生成前 20 个斐波那契数」 | `cloud:net=none;in=0;out=1` | **放行** → EXECUTE 在无人过问下跑完，产物正确 |

两次都符合规格。但它们合起来说出一件事先没想到的事：

> **绝大多数有用的 cloud_shell 调用都带 inputs**，因为要算的数据就在 workspace 里。
> 于是这条规则实际覆盖的是「不需要任何本地数据的计算」那一小块。

【定】**不因此放宽**。这一条的全部论证是「效果等价于一次 workspace 内的写」，
而一次 workspace 内的写**不会把任何东西送出去** —— 带上传之后那个等价关系就不成立了。
想把带 inputs 的也放进来，需要的是另一套论证（「送到用户自己的、断网的、用完即毁的沙箱，
出不去也留不下」），而那套论证现在**拿不出证据**：沙箱确实断网且会销毁，但
「池子与云账号本身没被攻破」不是 Atlas 能证明的事。按本仓的规矩，拿不出证据就不写进【定】。

登记为待定：带 inputs 的断网调用要不要放行，要一份单独的 ADR 与它自己的证据。

> **已由 [ADR-0018](0018-带上传的断网云沙箱调用经显式信任声明放行.md) 回答**：Atlas 仍然证明不了
> 「池子与云账号没被攻破」，所以它**不由 Atlas 判定**，而交给能回答它的人 ——
> 部署配置里显式声明 `trustUploadsToPool: true` 才放行，默认关；出网照旧不放行；事实表一字不改。

## Eval Evidence

- `verify:cloud` I 段：两条合取各有一个能单独触发的反向判据
  （断网无上传放行 ↔ 开网不放行 ↔ 有 inputs 不放行），
  外加「`run_shell` 的 EXECUTE 仍然不放行」与「写工具照旧放行」两条配对。
- 注入实测：把三条合取逐个摘掉、以及把整支改成无条件放行，各自翻红。
- `run_shell` 的 EXECUTE **仍然不放行**（同段反向钉住）—— 这一支只开给 `cloud_shell`。
- ⚠️ 两处守卫重叠已如实写明：`net=none` 与 `DATA_LEAVES_HOST` 互相遮蔽
  （resolver 一开网就必然标后者）、`scope.kind` 与 `cloud:` 前缀互相遮蔽。
  单摘任一道判据都不红，判别力由「两道同摘」与「把自动放行开给所有 EXECUTE」两条注入承担。
  保留显式分支的理由与 ADR-0012 在 `policy.ts` 的处置一字不差。
- live 验证如上表：正向（放行且真的执行了）与反向（有 inputs 就不放行）各一次。
