# ADR-0007：HTML 的**结构转换**可以内置，**语义挑选**不可以

> 状态：ACCEPTED
> 日期：2026-08-30
> 对应决策点：阶段 3.5 决 1（HTML→Markdown 落在 `fetch_url` 的 `as` 参数）、决 2（引入 turndown）
> 影响的架构条款：阶段 3 决 1（不建 `cases/web-archive`）、V05 §11.4（Materialization）、§16.1（固定开销）
> 证据来源：Run `run_9610d44d3a62` 的 trace；`verify:tools` I 段
> 顺带改动：本 ADR 记录**工程基线变更** —— 运行期依赖从 2 个增加到 3 个

## Problem

`fetch-url.ts` 的文件头有一条从阶段 3 起就在的【定】：

> **不得内置任何「正文提取」逻辑。** 从 HTML 里挑正文是**网页归档这个 Case 的业务语义**。
> 一旦写进通用工具，决 1（阶段 3 不建 `cases/web-archive`）就被从内部绕过去了 ——
> 而这件事三道 grep 闸门一条都拦不住，只有人读代码时守得住。

这条规则是对的，而且它守住了一件真东西。但 2026-08-30 的实测暴露了它**没有覆盖到的**一件事。

Run `run_9610d44d3a62`（任务：抓 `pi.dev/news/releases/0.84.3` 归档成 zip）：

| 事件 | 数字 |
|---|---|
| `fetch_url` 取回 | 40311 字节 HTML |
| 外置成 blob | `approxTokens: 16114` |
| 模型连调 `read_blob` | **3 次**，把它整个搬回上下文 |
| ContextFrame 从 → 到 | 4363 → 20621 token |

**外置在这条链路上净收益为零。** 而且问题不在下游：`read_blob` 的按行＋按字符分页
做得是对的（那正是阶段 3 为「一行 JSON」形态专门做的）。问题在上游 ——
**送进去的东西本身有九成是标签**。

所以要决：这九成标签能不能在 `fetch_url` 里就去掉？而去掉它算不算「内置正文提取」？

## Hypothesis

做决策时的认知状态：**「不做正文提取」这条规则里其实混着两件不同的事**，
而它们的判据不同。

## 判据：换一个 Case，结论会不会变

这是本 ADR 的全部内容。

| | 例子 | 换个 Case 结论变吗 | 归类 |
|---|---|---|---|
| `<h1>` 该不该变成 `#` | 办公归档要、代码读文档要、聊天看链接也要 | **不变** | **结构转换** |
| `<script>` 里的压缩 JS 要不要进上下文 | 三个场景都不要 | **不变** | **结构转换** |
| 导航栏要不要留 | 归档场景要丢；「帮我看这站有哪些板块」场景恰恰只要它 | **变** | **语义挑选** |
| 哪一块是正文 | 同上 | **变** | **语义挑选** |

**结论：结构转换是 Case 无关的，可以内置；语义挑选是业务判断，仍然不做。**

阶段 3 那条【定】因此**一个字都不用改** —— 它说的是「正文提取」，
而正文提取属于右边那一列。本 ADR 只是把它内部的线画出来。

## Alternatives

| 方案 | 优点 | 代价 | 何时会后悔 |
|---|---|---|---|
| A. 什么都不做 | 零成本，规则最干净 | 每抓一个网页多烧一万多 token，且没有任何东西会报警 | 已经后悔过一次了（上面那个 Run） |
| B. 新增 `html_to_markdown` 工具 | 更通用（本地 .html 也能转） | +180 token 固定开销；**且修不了实测那条链路** —— 模型仍要先 `fetch_url` 拿到大 HTML、进 blob、再取回来转 | 发现工具数涨了而那条链路没变时 |
| **C. `fetch_url` 加 `as` 参数（选中）** | **在源头就把结果变小**，转完往往根本不需要外置；不增加工具数 | 本地 `.html` 文件转不了（目前没有实测证据说明需要） | 真出现「读本地 HTML 文件」的场景时 —— 那时再加 B，有证据 |
| D. 内置 readability 挑正文 | token 削减最狠 | **越过上面那条线**，把决 1 从内部绕过去 | 第一次有人要「盘点这个站有哪些板块」时 |

## Decision

**决 1**：HTML→Markdown 落在 `fetch_url` 的 `as` 参数上（`"markdown"` | `"raw"`）。

**默认值是 `markdown`，不是 `raw`。** 这一条是刻意的，理由是摸底考试题 3 那条教训：

> 模型的分析全对，但它没有调那个更贵的工具。
> **一个需要模型主动选择才生效的优化，在真实运行里等于不存在。**

而这里默认值选错的代价是每次抓网页多烧一万多 token，且不会报警。所以默认值放在
「多数情况下正确」的那一侧：抓网页九成是为了读内容。要读 meta / 属性 / 内联脚本的
那一成，显式传 `as="raw"`。

**只对 `text/html` 生效**。JSON / 纯文本 / XML 一律原样返回 —— 把一份 JSON 喂给
HTML 转换器，出来的是一份**看起来像文本、但结构已被破坏**的东西，而模型看不出来。

**决 2**：用 `turndown`，不自己手写。

## 工程基线变更（这一条要单独说）

本仓 CLAUDE.md 原本写着：

> 运行期依赖只有 `@anthropic-ai/sdk` 和 `dotenv`

**这条基线本 ADR 破了。** 现在是三个，多出来的是 `turndown`（`@mixmark-io/domino` 是它的传递依赖）。

磁盘占用如实记：`turndown` 208K ＋ `@mixmark-io/domino` **8.6M**。
（Claude Code 的注释里写的「~1.4MB」是打包后的体积，不是 node_modules 的体积。）

不手写的理由：手写要在没有 DOM 的 Node 里解析任意 HTML，而
**「差不多能解析」的 HTML 处理正是最容易出静默错误的一类代码** ——
它不会报错，只会在某些页面上少转一块，而模型没有任何办法发现自己拿到的不完整。
这与本仓「转不动就如实说转不动，不返回半成品」的口径是同一条：
我们能接受「不做」，不能接受「做了一半而不知道」。

## Consequences

### 好的

- 实测 `pi.dev/news/releases/0.84.3`：**38280 → 13023 字符（削减 66%）**，
  ≈15312 → ≈5210 token。原链路上那 3 次 `read_blob` 直接消失。
- 不增加工具数，固定开销起步价不变。
- `as="raw"` 保留了退路 —— 要抠 meta 标签或内联脚本时仍然拿得到原文。

### 坏的 / 要盯的

- **多一个运行期依赖，多 8.8M 磁盘。** 这是真代价，写进 CLAUDE.md 的工程基线里。
- **本地 `.html` 文件仍然转不了。** 目前没有实测证据说明需要，等有了再加 B 方案。
- **转换质量取决于 turndown。** 它转不动时回原文并说明（不返回半成品），
  但「转出来但转得难看」这一类我们无法机械发现。

### 这条线怎么守

【定】`verify:tools` I 段有一条判据：**转换后导航与页脚文本必须仍然在**。

它红了说明有人加了 readability 那类规则，从内部把决 1 绕过去了 ——
而这正是阶段 3 那条【定】担心的事，只是现在它有机械判据了，
不再「只有人读代码时守得住」。

判别力实测（2026-08-30 真跑过）：往 `html-to-markdown.ts` 的
`service.remove([...])` 里加上 `"nav"` 和 `"footer"`，这条判据**当场翻红**。

同批还实测过另一条：把默认值从 `markdown` 改回 `raw`，「① 默认转换」当场翻红。
