# ADR-0014：「观察过期」的拒绝不计入连续失败；只读外部状态的批不按入参判打转

- 日期：2026-10-03
- 状态：已采纳（用户拍板：「按照你建议的来」）
- 修订：[ADR-0013](0013-本机-computer-use-图像进模型轨道与自建-Swift-助手.md) 的代价 ⑥⑦（由「如实提示、不改规则」改为本 ADR 的规则）
- 附带：第一次真桌面运行暴露的截图几何 bug（见文末「附带修复」）

## Problem

ADR-0013 时两条 Runtime 既有规则与 GUI 的交互被如实登记、没有改：

| 规则 | GUI 任务里的后果（`verify:computer` N 段当时实测） |
|---|---|
| 连续失败只在「必需验证通过」时清零 | GUI 动作没有独立核实 → 它是**整个 Run 的累计拒绝数**；屏幕一动导致的拒绝也算，默认 3 次就结束 |
| Progress Guard：连续三批完全相同 ＝ 原地打转 | `screenshot` 入参恒为空 → 等界面加载时连截三次就 `NO_PROGRESS` |

两条都会让一个**做得对**的 GUI Run 被提前结束。

## Hypothesis

两条规则的隐含假设在 GUI 上不成立，而不是规则本身错了：

1. 「失败」的隐含意思是「有人做错了」。执行前核对发现**世界在观察之后变了**，模型照着当时的截图做，
   没有错；工具拒绝，也没有错。它不是失败，是「先去重新看一眼」。
2. 「入参相同 ⇒ 结果相同」只对读 transcript 之内状态的调用成立。读外部状态时，相同入参每次看到的可以完全不同。

## Alternatives

| 方案 | 代价 | 何时会后悔 |
|---|---|---|
| A. 只提示、不改（ADR-0013 的处置） | 做对了的 Run 被提前结束 | 第一次真实 GUI 任务（已经发生：live 运行撞了 10/10） |
| B. 让 GUI 的 Verifier 报 PASSED 来清零计数 | 说假话（再截一张图不是独立核实） | 永远 —— 事实表上多一条「已核实」的假事实 |
| C. 一律调大 `--max-consecutive-failures` | 真正打转的 Run 也跑得更久 | 模型真的连错十次时 |
| **D. 按「谁错了」区分失败；按「读不读外部状态」区分打转** | 两条新的声明义务（见下） | 有工具滥用 `AFTER_REOBSERVATION` 来逃避计数时 |

## Decision

**选 D。**

### 一、`Retryability: "AFTER_REOBSERVATION"` ＋ `NOT_STARTED` 不计入连续失败

- 语义：「你依据的那次观察已经过期了；**什么都没做**；重新观察再来」。
- 【定】豁免是**合取**：`AFTER_REOBSERVATION` **且** `sideEffectState === "NOT_STARTED"`。
  副作用说不清的「过期」照常计数 —— 豁免的前提是这一下确实没发生过（`verify:budget` I 段 ② 钉着）。
- 只影响「要不要 +1」，不影响清零条件（清零仍然只认必需验证通过）。
- 不与 `AFTER_ENVIRONMENT_CHANGE` 合并：那一个是「等外部世界变」（服务恢复、授权到位），
  重新观察解决不了；这一个是「世界已经变了，你还没看见」。

**哪些拒绝是「过期」**（`tools/computer/src/handler.ts`）：目标处窗口在截图之后换了 / 出现 / 消失、
目标处画面变了、那张截图已失效、本进程里还没截过图。
**哪些不是**：截图时那里就是白名单外的窗口或桌面（模型瞄错了）、非法按键、前台不在白名单、
安全输入开着、缺授权 —— 照常计入。

【定】为此 handler 的检查顺序改成**先问「变没变」，再问「许不许」**。反过来排的话，
「截图后冒出一个 Finder 窗口」会被记成模型瞄错了白名单外的窗口（NOT_ALLOWED，计入）——
两种拒绝都什么都不投递，差别只在**谁错了**，而计数要的正是这个差别。

### 二、全部由「只读、读外部状态」的调用组成的批：不按入参判打转，并**重置**计数

- 判定由**声明**推出：`stateOutsideTranscript === true && idempotency.isReadOnly`（截图、只读档 MCP 快照），
  读的是冻结的工具快照，不按名字。
- 重置而不是「跳过、不碰计数」：守卫的理由是「第三次还一模一样，说明模型没有在读反馈」，
  而一个只做观察的批**就是在读反馈**。于是 [点 A] [截图] [点 A] [截图] [点 A] 不算打转。
- 兜底是轮次预算：一直只截图的 Run 最终撞 `MAX_TURNS`，不会永远跑下去。

## Consequences

### 接受的代价

1. **一条新的声明义务**：工具只有在「确实什么都没做、而且原因是观察过期」时才可以用 `AFTER_REOBSERVATION`。
   滥用它就能逃避计数 —— 合取里的 `NOT_STARTED` 挡住一半，另一半只能靠工具作者诚实（与 `isIdempotent` 同类）。
2. **剩余盲区**：「动作 ＋ 截图」的批照旧按入参判 —— 同一处连滚三次（[滚动, 截图] ×3）仍会被判打转。
   豁免只覆盖纯观察的批，这是用户拍板的范围；`verify:computer` N 段钉着它、启动提示如实说。
   更好的判据是「观察结果有没有变」（截图内容 hash），那是 V05 §16.2 推后的第二种形态，需要另一个决定。
3. **模型自己的错误仍是累计数**：成功的 GUI 动作没有独立核实、不会清零它。启动提示继续建议 `--max-consecutive-failures 10`。

### 重新评估的触发条件

- 出现第二个产出 `AFTER_REOBSERVATION` 的工具（检查它是否真的满足语义）；
- live 运行里「动作 ＋ 截图」的重复批被误判打转。

## 附带修复：截图几何（第一次真桌面运行，2026-10-03）

真实端点 × 真实桌面的第一次运行（`run_609acf77238c`，qwen3.8-flash，计算器 ＋ 文本编辑）撞了
`consecutiveFailures 10/10`。逐条回源：

| 现象 | 原因 |
|---|---|
| 截图报 ScreenCaptureKit `-3811` | `SCContentFilter(display:including:)` 在白名单窗口一个都不在当前桌面时（用户的 Claude 窗口在全屏 Space 里）无内容可截 |
| 每一次点击都落在空白处 | 同一个过滤器在 macOS 26 下截的**不是整块显示器**，而是白名单窗口的外接矩形、再等比放大：计算器在窗口表里是 (446,559) 230×408 pt，在图里是 (318,605) 290×515 px（×1.26 加平移）。Atlas 按「图 = 整块显示器」换算 —— **模型读图是对的，Atlas 的换算是错的**，且不报错 |
| 我先怀疑的「思考开关」 | P-6 用那张真实截图 ＋ Atlas 真实工具面重放：qwen3.8-flash 默认思考 **13/14**、关闭思考 **1/14**（多数给出畸形 x/y）。不是原因 —— 也说明「关思考更准」那条阶段 0 结论只对 coordinate 数组形态成立 |

修法（助手重建 → 用户需重新授权一次）：

- 改用「排除其余所有应用」的过滤器，内容区是整块主显示器；`sourceRect` 显式写成整块显示器；
- 驱动把 **`contentRect`**（图实际覆盖的屏幕区域）报回来，`toPoints` 与区域比对一律经它换算 ——
  「图覆盖哪里」从一个默认变成一条事实（`verify:computer` E 段用偏移的 contentRect 钉着）；
- 白名单应用不在当前桌面时得到空白图（handler 如实提示 activate_app），而不是一个错误。

### 之后两次真桌面运行又抓到的三条（都在助手里，都是「喂给判定的事实是旧的或多的」）

| 运行 | 现象 | 原因 → 修法 |
|---|---|---|
| 修复几何后的截图自检 | 截图里出现了**用户桌面上的文件夹名与文件名** | 「排除其余应用」配 `excludingDesktopWindows(true)` 时桌面图标层不在可共享列表里、不会被排除 → 改为按**窗口**排除、桌面窗口一并列入：不属于白名单应用的窗口一律排除 |
| `run_73db9f5de54f` | 计算器 6 次真实点击全部成功、读出 888；文本编辑里**每一次键盘输入都被拒**（「前台是 Claude」） | 助手跑在 `dispatchMain()` 上，主 run loop 不转，`NSWorkspace.frontmostApplication` 停在第一次被读的那一刻 —— 判定是对的，前台这条事实是旧的 → 改问辅助功能的焦点应用（现查），退路是窗口表最上层普通窗口的主人；`capturedApps` 同病，改由现查的窗口表推出 |
| 同上 | Run 结算 `SUCCESS`，而模型自己的总结明说「打字那一步没做成」、请人接管也无人应答 | **不是本 ADR 的范围**：没有任务级完成契约（ADR-0013 CU-9 / S5-7）。如实登记 —— 结算看不见「必需却未完成的 GUI 步骤」 |

**第四次运行（`run_800091ccaf65`，三处修复之后）端到端完成**：计算器上 AC → 3 → 7 → × → 2 → 4 → =，
从清零状态读出 888；文本编辑 `cmd+n` 新建「未命名 2」、输入「37 × 24 = 888」，不保存、不关窗口。
事后独立截图核对：文档内容与标题「未命名 2 — 已编辑」都在。途中一次 STATE_CHANGED（截图后文本编辑回到前台
盖住了计算器）按 ADR-0014 不计失败，模型重新截图后继续。它还**自发**把截图落进 workspace、用 `run_shell`
做像素分析定位按键中心，完成后把这些临时文件删了 —— 一个工具组合，不是 Harness 教它的。

模型在第三次运行里的行为值得记：键盘一直被拒时，它试了几种正当的变体、想用剪贴板中转（被沙箱拦住，
它没有继续绕），然后 `request_handoff`，最后在总结里**明说没做成**、不假装。Harness 的结算反而是那句假话。

**教训**：阶段 0 用的是合成界面（自己渲染的整屏 PNG），截图几何恰好永远是「整块显示器」——
真实的 ScreenCaptureKit 那一跳从来没有被测过。又一次「判据打在下游，跨不过出事的那一跳」，
这一次跨不过去的是操作系统。

## Interview Narrative

两条规则都没错，错的是它们的隐含假设：「失败」默认有人做错了，「入参相同」默认结果相同。
GUI 让这两个假设第一次不成立 —— 屏幕在你看过之后变了，不是任何人的错；同一个截图请求，每次看到的都不一样。
所以按「谁错了」区分失败、按「读不读外部状态」区分打转，并且两处都用合取或声明把豁免的边界钉死。
而第一次真桌面运行告诉我们，真正挡路的还不是这两条规则，是一个合成界面永远测不出来的截图几何 bug。
