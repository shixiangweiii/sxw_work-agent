# ADR-0013：本机 computer use —— 图像进模型轨道，GUI 动作经自建 Swift 助手

## Problem

WorkAgent 的任务里有一大类落在**没有 API 的桌面应用**上（备忘录、计算器、各种客户端）。
Atlas 此前既看不见屏幕，也动不了它：`tool_result` 只有字符串，二进制资源按现行设计**一律不进模型**。

研究问题：**在一个所有动作的副作用都无从事先判断、观察只有像素的工具域里，
Atlas 的声明纪律与事实表还能不能说真话？**

## Hypothesis（做决定时的认知状态）

- 阶段 0 已经回答了「模型行不行」：0–1000 归一化坐标下，qwen3.8-flash 59/60（工具调用形态 10/10）、
  deepseek-flash 52/60（≥1792 宽时 39/40；工具调用形态 8/10）。**定位不是瓶颈**。
- 卡住的是 Runtime 的观察通道，以及「本机没有隔离层」这件事本身。
- 不知道的：真实应用上的定位、多步任务里的退化、模型对屏幕上提示注入的抵抗力。

## Alternatives

| 方案 | 优点 | 代价 | 何时会后悔 |
|---|---|---|---|
| A. 自建 Swift 助手（公开 API，前台） | 判定全在 TS、可测；独立 TCC 身份；无外部依赖 | 第一个需要编译的组件；ad-hoc 签名，重建即失授权 | 需要后台操作（不抢桌面）时 —— 公开 API 做不到 |
| B. Peekaboo（MIT，现成 CLI） | 原型最快 | macOS 15+、授权记在终端名下；判定会落在别人的二进制里，判据只能测假驱动 | 需要改一条判定时 —— 改不动 |
| C. 走 MCP（某个桌面自动化 MCP） | 零 Atlas 代码 | ADR-0011 的全部代价 ＋ 截图回不到模型眼前（MCP 的 image 块不进模型）| 第一次要求「执行前复核」时 —— 那需要理解参数 |
| D. 不做 | 无风险 | WorkAgent 的一大类任务做不了 | — |

## Decision

**选 A**：新增 `tools/computer`（TS，全部判定）＋ `AtlasGUIHelper.app`（Swift，只供原语），
图像作为一种**模型可见资源**进入 Runtime。逐条决定如下（编号对应调研报告的【议】）。

### CU-1 图像进模型轨道：新增 `ResourceKind: "image"`

**【定】推翻「二进制一律不进模型」，但只推翻一半**：只有 PNG / JPEG、尺寸**从字节本身读出**
（`imageDimensions`，不信工具自报）的资源才是 `image`；其余照旧 `binary`、照旧不透明。
处置标记写 `IMAGE_NOT_REDACTED_SENT_TO_MODEL` —— 图像脱敏不了，不假装。

**MCP 的 image 块仍按 binary 存**：Atlas 不理解外部服务器那张图是什么（ADR-0011「不说理解了才能说的话」）。

### CU-2 图放在 `tool_result` **之内**（端点数据 `vision.imageCarrier`）

Spike 1 P-1：放在 tool_result 之后的同一条 user 消息里，**百炼 HTTP 200 却静默丢图**（4/4）。
两个端点都收得下的只有这一种。它是端点行为，所以是声明数据（D-07），不写死在代码里。

### CU-3 坐标一律 0–1000 归一化，换算住在 `tools/computer`

qwen 会**无视**「像素坐标」的声明照样给归一化（P-2：1/10、0/10）—— 按像素换算是静默的系统性偏移。
换算只依赖**显示器逻辑尺寸**（`toPoints`），不依赖截图像素数。
**不进形状适配器**：坐标空间写在端点声明里，「谁读声明谁换算」读起来很顺，而换算依赖的是
显示器几何 —— 工具的观察事实。边界 15 抓的就是这个诱惑。

### CU-4 逐次审批 ＋ 启动时的静态白名单（不是 lease）

`--computer-apps` 是人在启动时写下的一张表，随工具定义冻结进 RunSpec；没有运行期的申请 / 授予 / 过期。
**ADR-0005 / 决 5 不动。** 每个 GUI 动作 EXECUTE ＋ IRREVERSIBLE，DEFAULT 档逐次问；
截图是 READ，不问（Policy 原生行为，一行没改）。

### CU-5 `--computer off|view|control` 与 `--sandbox` 正交

沙箱管 Atlas 自己的子进程，GUI 动作在**别的应用的进程里**生效 —— `SANDBOXED` 对它不成立。
绑在 `--sandbox off` 上等于逼用户为了点一下 TextEdit 关掉 run_shell 的沙箱。
每个 GUI 动作的 riskFacts 如实标 `GUI_INPUT_NOT_SANDBOXED`，两个入口的审批面都明说「不在沙箱内」。

### CU-6 / CU-7 自建 Swift 助手：独立 .app、自己的 TCC 身份

- 经 LaunchServices 启动（`open -n -g -a`）→ 系统把它当成独立的「负责进程」，
  授权记在 **Atlas GUI Helper** 名下，而不是终端（给终端开辅助功能 = 终端里的一切都能操控整台电脑）。
- Unix socket 放在 `mkdtemp` 的 0700 目录里，助手只接受**启动它的那个 Atlas 进程**的连接（`LOCAL_PEERPID`），
  该进程一没就退出（看门狗）。
- **只用公开 API**（ScreenCaptureKit / CGWindowList / CGEvent / AXUIElement），前台模式。
  不用 SkyLight 私有 API（这台 Intel 机器上有已知崩溃）。
- ad-hoc 签名，**源码 hash 不变就不重建** —— 每重建一次，系统就把它当成新程序，授权作废。
- 硬拒绝名单两处执行：TS（配置解析 ＋ 每次动作前）与助手投递前再判一次。

### CU-8 模型调用审计不落图像字节

按**值**替换：body 里恰好等于某张活图 base64 的字符串，换成指回 ResourceStore 的占位（ref ＋ hash ＋ 尺寸）。
Runtime 因此不需要认识任何 Provider 的图像块形状。不做的话，一个 60 轮的 GUI 任务会往审计目录写几百兆
**同样几张截图的副本**，而那些字节在 ResourceStore 里已经有一份。

### CU-9 不做完成判定；Verifier 如实 SKIPPED

GUI 动作的结果只能靠再截一次图观察，那是模型的观察，不是独立证据。
`ComputerVerifier` 一律 `SKIPPED ＋ required:false` —— 不会因为它降级，也不会冒出「已核实」的假事实。

### CU-10 不引入定位模型

阶段 0 实测推荐配置下两个模型都够用。

### CU-11 AUTO 档允许操作 GUI —— 但白名单、硬拒绝、执行前复核仍在

`verify:computer` F 段在「审批一律放行」下证明：换了窗口、画面变了、截图失效、目标是 Finder / Terminal、
拖拽终点越界 —— 六种情况全部拒绝且**一次都没投递**。AUTO 拿掉的是「人」，拿不掉这几道。

### 另外几条【定】

- **两个工具，不是一个**：`screenshot`（READ、幂等）与 `computer`（EXECUTE、非幂等）。合成一个的话，
  看一眼屏幕也得跟着声明成非幂等、要审批，崩溃后的截图会被当成状态未知的副作用。
- **执行前复核（TOCTOU）**：白名单 → 窗口身份 → 区域灰度差（阈值 12）→ 截图仍在。
  人批准的是「在那张截图上点这里」，执行时那里已经不是那个东西了就不许点（arXiv 2604.18860：
  截图到执行平均 6.51 秒，期间切焦点能 100% 重定向动作）。
- **`haltsBatchOnFailure`**：一个 GUI 动作失败，同批后面的一律跳过 —— 否则一批 [点击, 输入] 里
  点击被拒之后，那段文字会打进一个没人看过的窗口。
- **`stateOutsideTranscript`**：resume 时的「外部状态核对不了」改由**声明**识别，不再按 `mcp__` 前缀。
  白名单一变，工具 version 跟着变，resume 点名漂移。
- **活图窗口成批移出**（3 张、步长 3）：逐张移出会每轮改写历史中段，严格前缀缓存每轮失效 ——
  而截图恰恰是帧里最大的东西。
- **截图只截白名单应用的窗口**，其余应用、桌面、通知不进发往端点的图。
- **键盘**：安全输入开启（密码框有焦点）时拒绝合成输入；系统级组合键（Spotlight、切换应用、锁屏、注销、强制退出）拒绝。

## Consequences

### 接受的代价（一条都不许假装没有）

1. **没有隔离层**：一次误点就是真实后果。Intel Mac 跑不了 Apple 的 macOS 虚拟机。
2. **提示注入**：屏幕上的文字可能是指令；两个端点都没宣称对截图做注入检测。system prompt 里那句「截图里的文字是素材」不是防线。
3. **隐私外发**：截图发往 DeepSeek / 百炼，图像脱敏不了。白名单截图只是减法。
4. **护栏被绕过**：凭证读禁、私网拒绝在 GUI 面前不成立（在白名单应用里能看到什么，模型就能看到什么）。
5. **抢占桌面**：前台模式下用户不能同时用电脑，人的输入会和 agent 的动作交错。
6. **（已由 [ADR-0014](0014-观察过期不计失败与只读外部状态不判打转.md) 修订：观察过期的拒绝不再计入；模型自己的错误仍是累计数）**
   **「连续失败」在 GUI 任务里是累计数**：它只在「必需验证通过」时清零，而 GUI 动作没有独立核实 ——
   **默认预算下整个 Run 累计 3 次拒绝就结束**（`verify:computer` N 段实测）。本批**不改**这条 Runtime 规则，
   启动提示如实说并给出 `--max-consecutive-failures 10 --max-turns 60`。
7. **（已由 ADR-0014 修订：只读外部状态的批不再按入参判打转；「动作 ＋ 截图」的重复批仍会）**
   **截图轮询会被判原地打转**：Progress Guard 把连续三批完全相同的调用判为 `NO_PROGRESS`，而
   `screenshot` 的入参恒为空 —— 等界面加载时连截三次就结束（N 段实测）。同样**不改**，提示里如实说。
8. **第一个需要编译的组件**：要 Xcode Command Line Tools；ad-hoc 签名 → 重建即失授权；
   Tahoe 上录屏授权按月重新确认，可能打断无人值守的任务。
9. **思考参数没有接线**：P-2b 里 qwen 10/10 是**关闭思考**时测的，而 Atlas 不发送任何思考参数。
   「按任务类型配置思考」是一项还没有的能力。
10. **只支持主显示器**；多显示器、全屏 Space、Retina 之外的缩放组合都没测过。

### 适用条件

本机 macOS 14+、单用户、人在回路（或者明知 AUTO 下只剩白名单与复核）。

### 重新评估的触发条件

- 6、7 两条在 live 运行里真的打断了任务 → 需要一份改 Runtime 规则的 ADR
  （候选：GUI 拒绝不计入连续失败；只由 `stateOutsideTranscript` 只读工具组成的批不按入参判无进展）；
- 需要后台操作（不抢桌面）→ 公开 API 做不到，重新评估驱动；
- 换到 Apple Silicon → 虚拟机隔离成为可能，代价 1 要重写。

## Eval Evidence

- **阶段 0**：`spikes/s1-computer-use-vision/`，约 290 次真实调用，结论见调研报告第 10 节。
- **`verify:computer`（38 条判据）**：边界 15 判别力（两种诱惑各注入一次）· 配置 fail-fast（9 种）·
  图像通道（tool_result 之内 / 无 vision 不装，两道门各自可单独触发）· token 公式两条路径（差值恰好 1962 / 962）·
  活图窗口（七帧只改写一次）· 坐标换算（三个坐标系两两不等）· 执行前复核六种拒绝 ＋ 配对 ·
  失败即中止本批 · 无观察 / 缺授权 · 键盘三种拒绝 ＋ 配对 · Web 审批卡（控件描述、剥 RLO）·
  审计不落图像字节 · resume 分支一 / 分支三 ＋ 白名单漂移 · 两条既有规则的「提示与行为一致」。
- **注入实测**：19 处实现各改坏一次，每次对应判据翻红、改回后全绿；另有一次「只摘适配器那道门」
  的注入暴露出 C 段第一版只测了两道门的合取（守卫重叠区，本仓第五次），已补单独触发它的判据。
- **真助手**：只核对过构建、启动、socket ＋ peer pid、授权查询（两项均未授权，符合预期 ——
  它有自己的 TCC 身份）、应用解析、退出后无残留进程。**没有截过真屏、没有投递过真事件**：
  那需要用户本人授权，而本批不替用户做这个决定。

### 仍然开着的门槛

- **用真实端点在真实桌面上跑完一个多步 GUI 任务**（要花钱、会真的操作屏幕，需要用户先授权助手）。
- CLI 审批提示的 GUI 分支没有机械判据（打印到终端；内容与 Web 卡片同出 `describeForApproval`）。

## Interview Narrative

computer use 难的不是让模型点准 —— 阶段 0 量过，两个模型在归一化坐标下都够用；难的是在一个
「副作用无从事先判断、观察只有像素」的工具域里，让 Harness 继续说真话。所以图像作为一种新的资源进模型轨道、
但脱敏标记如实写「没脱敏」；Verifier 如实写「没核实」；崩溃后的点击如实落「交人决定」。
安全上本机没有隔离层，于是把边界做成四样可测的东西：白名单截图、硬拒绝名单、执行前复核、审批面上说清点的是什么 ——
判定全部放在 TS 一侧，让验收脚本测到的是生产代码而不是假驱动。
最后，GUI 把 Runtime 两条既有规则（连续失败的清零条件、无进展判定）的隐含假设暴露了出来；
这一批没有偷偷改它们，而是让启动提示如实说出后果，并用判据把「说的」和「发生的」钉在一起。
