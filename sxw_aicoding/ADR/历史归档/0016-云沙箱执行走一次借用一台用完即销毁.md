# ADR-0016：云沙箱执行走「一次借用一台、用完即销毁」，依赖烤进模板

- 日期：2026-10-16
- 状态：已采纳
- 关联：[ADR-0012](0012-审批与执行特权是两条正交的档位轴.md)（审批与执行特权两条轴）、
  [ADR-0011](0011-通过外部-MCP-接入浏览器能力.md)（外部能力的接法与代价记账）、
  [ADR-0010](0010-二进制交付物走字节通道与按路径声明.md)（产物按字节登记）

## Problem

`run_shell` 只在 macOS 上存在（seatbelt 是它的边界，`isSandboxAvailable()` 在非 darwin 上
把它整个摘出工具面）。而 ADR-0012 把审批做成一条轴之后，EXECUTE 的代价仍然压在人身上：
那十几次确认之所以必要，是因为**一条本机命令的副作用范围说不清楚** ——
它能碰 workspace、能碰 `$HOME`（UNRESTRICTED 档）、能联网、崩在中途时「做没做」无从判断。

用户自建了一个基于阿里云 FC Agent Sandbox 的沙箱池服务（`sxw_fc-sandbox`）：
HTTP 借一台隔离的 microVM，**归还即销毁**，Atlas 不持有云端 Key。
问题是：把执行挪到那上面，能不能让「这次执行的副作用是什么」变成一句**可以证明**的话。

## Decision

新增 `tools/cloud-sandbox`（`@workagent/tools-cloud-sandbox`），提供一个工具 `cloud_shell`。

### 1. 独立工具，不做 `run_shell` 的后端

同一个工具名随环境换语义，正是 `isSandboxAvailable()` 那条【定】反对的「边界随环境悄悄变」。
而且两者**看不到同一个文件系统** —— 这是真正的分水岭，两边的 description 成对写死它
（ADR-0008 的教训：只改一边会让模型在两者之间随机选）。

顺带修掉 ADR-0012 代价④：非 darwin 上终于有了一个 EXECUTE 能力。

### 2. 每次调用借一次，归还即销毁

【定】不跨调用持有沙箱。与阶段 3.5 拒绝持久 cwd 同理（transcript 之外的隐藏状态），
但**决定性的理由是第 5 条那个研究问题的前提**：沙箱跨调用存活，第 N 次调用就能给
第 N+1 次留东西，「副作用恰好等于声明过的那几个文件」当场不成立。

回源核对过「整个 Run 持有一台」那条路，三条硬事实让它不成立：

| | |
|---|---|
| 工具拿不到 Run 身份 | `ToolExecutionContext` 只有 signal / workspaceRoot / onProgress / timezone / executionPrivilege |
| 没有「Run 结束了」这个收敛点 | `run-loop` 的 `finish()` 只收敛循环终态；`RECOVERY_REQUIRED` 从 facade 自己返回；**崩溃没有出口**。computer use 那批刚因为「零消费者」删掉过 `ComputerRuntime.close()` |
| 等人发生在**工具调用内部** | `waitsForHumanInteraction` 让 Run 进 `WAITING_FOR_INTERACTION` 而进程阻塞在工具里；池子的借用**最长 60 分钟不可再续**。一次审批去吃个午饭回来，沙箱已经没了 |

### 3. 出网默认全禁，**读回平台回显核对之后**才发命令

两道闸门，与 `run_shell`（TS 判定 ＋ 沙箱）、computer use（TS 判定 ＋ 助手再判）同构：

```
闸门一（池子）：借出时下发 deny_out=0.0.0.0/0, allow_out=[]
闸门二（Atlas）：读回平台回显，对不上**拒绝执行**，绝不发命令
```

【定】`update_network` 返回成功只说明请求被接受了，**平台回显才说明它生效了**。
一条放行了却没验过的闸门，与「验过并通过」在事后不可区分。

### 4. 依赖烤进模板，不做跨调用缓存

装依赖与断网是缠在一起的：要装依赖就要开网，而开网就把「副作用可证明」丢了。
实测（见下）：预装模板在**断网**沙箱里直接 import 成功；现装要 32.2s **且必须开网**。
所以模板不是「更快的选项」，**是和断网相容的那个选项**。

Volume 做依赖缓存那条路被平台 500 挡住（疑似邀测未开通），降级为后续项。

### 5. 研究问题

> **当副作用的范围可以被机械地证明为「只有声明过的那几个文件」，EXECUTE 还需要逐次审批吗？**

一台断网 ＋ 没有输入 ＋ 用完即销毁的云 VM，对用户拥有的任何东西，durable effect 与
「往 workspace 写那几个文件」等价 —— 而后者按决 3 本来就自动放行。

**v1 照常逐次问**，auto-grant 要单独的 ADR。这里只把前提建起来：
per-call 让审批面是**完备的** —— 命令能看到什么，`inputs` 上全列着。

### 6. 工具契约

`verify:tools` B4 把自家工具锁在标量上，所以列表按行分隔（照 `ask_user` 的 `options`）：

```
cloud_shell(command, description, inputs, outputs, network, timeout_ms,
            artifact_path, artifact_role)
```

- `network`：`"none"`（默认，彻底断网）或逗号分隔的域名白名单。
  写成字符串不是布尔，因为实测证明域名白名单的语义是正确的。
- `inputs` / `outputs`：按行一个相对路径，上传到沙箱同名相对位置 / 取回 workspace 同名相对位置。
- 新增 `EffectScope.kind: "REMOTE_SANDBOX"`，CLI 与 Web 成对展示。
  **不复用 `PROCESS`** —— 那一支会打印「只能写 workspace 与 $TMPDIR」，对云上是方向相反的保证（MCP 那批踩过）。

### 7. 护栏复用，不许抄第二份

| | |
|---|---|
| `inputs` | 过 `read-guard.ts` **那一份**，否则 `inputs=".env"` 一行绕过决 3 护栏① |
| `outputs` | 过 `writeBoundaryRefusal()` **那一份**；两个执行特权档下都不许逃出 workspace |
| 产物 | 按真实字节登记（ADR-0010），`artifactKindOf` 那一份决定跑哪些检查器 |
| `lease_id` | 是凭证，不进 output / 审批面 / 事件 / trace |

### 8. 恢复分支按调用区分

归还即销毁，所以 durable effect 恰好是取回来的那几个文件，而那是**可观察的**：

| | 分支 |
|---|---|
| `network="none"` | **二**（OBSERVE_FIRST）—— 拍 outputs 的前置指纹就能答「变没变」 |
| 开了域名 | **三**（RECOVERY_REQUIRED）—— 对外发过什么无从判断 |

决 6 说「分支判据是 Action 级事实，不是工具的静态声明」，所以这是**按调用**决定的。

### 9. 边界 grep 第 16 条

借用客户端不得进 `packages/` 与 `adapters/`。诱惑形态与 MCP 第 12 条同构：
把 HTTP 客户端搬进 `ports/` 叫「SandboxPort」看着天经地义，而边界 4/6/7 一条都不会响。

## Consequences（代价，一条都不许假装没有）

1. **依赖集合在模板构建时就定死了。** 模型要一个模板里没有的包，只有重建模板（71s，但要人去做）
   或这次调用开网（丢掉干净的性质）两条路。这不是新问题 —— 本机 `run_shell` 也是「宿主装了什么就有什么」。
2. **大输入每次重传。** 池子上传上限 64MB，一个数据集迭代十次就是十次上传。
3. **没有成本轴。** Atlas 第一个按秒计费的工具。per-call ＋ `maxToolCalls` 大致兜得住，
   **登记而不是造第 9 条轴**。
4. **`commands` 不流式。** 一条十分钟的命令，模型在结束前拿不到任何输出；
   `run_shell` 的 HEARTBEAT 在这里只能报「还在等」。
5. **`inputs` 非空 = 数据离开本机**，记 `DATA_LEAVES_HOST` ＋ `dataMovement`。**断网也照记** ——
   东西确实到了阿里云。
6. **内网不可达没有保证。** 实测分不出「平台拦了」和「那边没东西」，所以不依赖它、自己下发全禁。
7. **池子是单模板的**（它自己的已知限制）。v1 把池子指向预装模板，不做多模板。
8. **11 个预装包够不够用没有证据** —— 按「办公与抓取类」拍的，等真实任务回填。
   > 更正（2026-10-16，ADR-0017 批）：已回填。全量枚举基础镜像自带 105 个包、模板新增 6 个，共 111 个；
   > 「11 个」里有 5 个镜像本来就有。四类真实任务（CSV 统计、scipy 回归、jinja2 渲染、CSV→xlsx）没有一个缺包。

## Eval Evidence

### 阶段 0 摸底（真实云端，2026-10-16）

- 默认不传 `network`：**公网完全开放**；沙箱只有 `eth0 169.254.0.21/30` 一张网卡，
  所有路由 `via 169.254.0.22`，内网样本 timeout 但**每个目标都有路由** → 分不出拦没拦。
- `update_network` 对非 secure 沙箱接受、生效、可逆（0.15s），`get_info` 回显策略。
  deny-all **连 DNS 一起断**；域名白名单放行域名通、未放行 `000`。
  ⚠️ 域名过滤在 80/443 的 SNI 层，**裸 TCP 连接照样 connected** —— 拿它判「拦没拦」会假阴性。
- **入站裸奔**：沙箱里 `python3 -m http.server`，公网不带令牌请求返回 **200**。
- Volume：`create_volume` 成功，`volume_mounts` 一路 500（疑似邀测未开通）。

### 阶段 1 fc-sandbox 侧（219 条单测 ＋ 6 条注入 ＋ 真实云端）

- 新增 9 条判据（`tests/test_atlas_egress.py`），**每条配一个反向**：
  默认断网 ↔ 关掉配置时不得传；回显对不上拒绝 ↔ 对得上必须交付；
  超限报截断 ↔ 没超限不得报；超时交回部分输出。
- **6 条注入实测全部翻红**：摘掉 network/secure、无视配置恒传 deny-all、摘掉回显核对、
  读不到回显当通过、真实字节数照截断后报、超时丢掉输出。
- 真实云端 `probe_phase1_cloud.py` 六条全过，两条最要紧：
  **`secure=True` 没挡住 envd**（命令、文件、**丢缓存重连**都正常）；
  **入站探测从 200 变 403**。
