**日期**：2026-08-31
**状态**：已采纳（v1 交付，待真实端点实测反馈）

## 起因：一次真实的内网实测失败

用户跑「访问内网网页 → 归档」任务，第一步就断：页面需要内网登录，流程直接中断。

回源码定位，它撞上的是 `fetch_url` **两条已拍板【定】的交集**，两条都不是 bug：

| 断点 | 位置 | 行为 |
|---|---|---|
| A | `tools/common/src/net/url-guard.ts`（决 3 护栏 2） | 内网域名解析到私网地址 → 拒绝，且 `retryability: "NEVER"` |
| B | `tools/common/src/net/fetch-url.ts` 文件头【定】 | 不做登录态、不做 Cookie、不做浏览器 |

`NEVER` 意味着模型不会换写法重试——那是设计如此。所以这不是「修个 bug」能解决的，
**它要求反转一条已经拍板的决定**，因此需要这份 ADR。

---

## 决定

**接入外部 MCP 服务器，作为通用能力**：读配置 → 起 stdio 子进程 → `tools/list` →
翻译成 Atlas 的 `ToolSnapshot` → 进工具面。人在浏览器里登录，Atlas 只拿渲染后的内容。

### 为什么是 MCP，而不是给 `fetch_url` 加 cookie

**凭证从头到尾不进 Atlas。** 加 cookie 参数会立刻要求一整套凭证解析、脱敏与
Trace 隔离机制——而全仓没有那个东西（`SecretResolverPort` 那个空壳 2026-08-31
刚被删掉，注释写着「要做的那天先写实现」）。走 MCP 则一行凭证代码都不用写。

### 硬要求：换个 MCP 只改配置

用户的原话是「换个不是 playwright 的本地调用浏览器的 mcp，不改 atlas 代码只改配置就能正常工作」。
`tools/mcp/` 一个字都不认识 Playwright——工具名、数量、参数形状全部来自运行时的 `tools/list`。

## 参照 opencode，以及在哪里必须分叉

读了 `/Users/shixiangweii/WebstormProjects/opencode` 的 `packages/opencode/src/mcp/`。

### 它能通用的秘密：**不翻译 schema**

`catalog.ts` 的 `convertTool` 是全部抽象，约 40 行——`inputSchema` 原样展开交给
AI SDK 的 `dynamicTool`，**从不试图理解它**。

```
opencode :  MCP schema ────────────────────→ AI SDK jsonSchema() → provider
Atlas    :  MCP schema → 【JsonSchema 子集 + validateAndNormalize】→ 形状适配器 → provider
```

Atlas 中间那层不是冗余（撑着 `normalizedInput` / `inputDigest` / action identity /
Policy 的 `readPointer`），但**它就是"换个 MCP 就得改代码"的风险点**。

> ### 【定】不要枚举支持哪些 JSON Schema 构造
>
> 最自然的处置是「扩校验器支持 array / object / enum」。**不能这么写**：
> 枚举就永远有下一个构造（`$ref` / `oneOf` / `prefixItems` / …），
> 而下一个构造就是下一次「接个新 MCP 得改 Atlas 代码」。
>
> 改成**最小翻译**：`JsonSchemaProperty.type` 放宽成 `string | string[]` 且可缺失，
> 两个接口都加索引签名，`validateAndNormalize` 变成「认识的照校，**不认识的原样放行**」。
> 失败方向按外部工具定：拒绝一个不认识的构造，后果是**整个工具废掉**——
> 模型看得见它、调得动它，每次都被 Runtime 挡在门口，且它无从改对。

代价如实记：索引签名让 Atlas 自家工具的关键字拼写错误（`descripton`）不再被编译器抓住。
对价是 `verify:tools` **B4 段**——自家工具的属性必须是标量、且只带 `type` / `description`。

### 抄来的四条实战细节（读协议想不到，踩过才知道）

1. **`tools/list` 是分页的**——cursor 翻页，还要防重复 cursor 死循环
2. **`outputSchema` 会解析失败**——真实服务器发得出 SDK 解不开的 `$ref`，处置是把
   `outputSchema` 整个 omit 掉重试。**这条是引 SDK 最好的论据**：手写客户端根本不会
   预见到它，症状是「某个 server 一接就崩」
3. **`resetTimeoutOnProgress` 要配一个空的 `onprogress`**——SDK 只在这个回调存在时
   才发 progress token，少写它另一行静默失效
4. **`structuredContent` 兜底**——content 空但有结构化结果时要 stringify 回去

### 必须分叉的四条

| opencode | Atlas 抄不了的原因 | 处置 |
|---|---|---|
| `tools/list_changed` → 重新 list ＋ 发事件 | 工具面在 Run 启动时冻结进 `RunSpec` | **登记 handler 但只记日志**，不重新 list |
| `isError` → `throw` | Atlas 要 `ok` ＋ `sideEffectState` 二维 | 按档位分流（见下） |
| 无 effect / reversibility | Policy 判 Allow/Deny 需要 | 配置层补，默认最保守 |
| 无恢复分支 | §18.2 需要 | `execute` 档天然落分支三 |

第一条值得展开：跟着服务器改工具面的后果是**同一条 transcript 上的同一次 tool_use，
resume 时会走进另一条恢复分支，而盘上看不出来**。

## 声明的来源：只能是人

MCP 协议**一个** Atlas 必填字段都不提供。`Tool.annotations` 里有
`readOnlyHint` / `destructiveHint` / `idempotentHint`，看起来正好能填上。

> ### 【定】不读 `annotations`，一行都不读
>
> 它们是**服务器自述**的（MCP 规范自己写着是 untrusted hint）。拿它决定审批档位，
> 等于让**被审计方书写自己的审计规则**——与本仓已经拍板过的两条同源：
> `shouldUseSandbox` 的「命令名匹配不是安全边界」、以及「审批界面可被 ANSI 伪造」。

配置里一个词说三件事：

| 档位 | 含义 |
|---|---|
| `"read"` | 只读 ＋ 幂等 ＋ 自动放行 ＋ 报错时记 `NO_EFFECT` |
| `"execute"`（默认） | 非只读 ＋ 非幂等 ＋ 逐次审批 ＋ 报错时记 `UNKNOWN` |

**用 `read` 而不是 opencode 的 `allow`**：`allow` 表达偏好（"别问我"），
`read` 表达属性（"它只读"）。从"别问我"推出"所以它只读"是一次不成立的合并——
一个人完全可能想给某个写工具免审批，那时 Atlas 会跟着把它记成"没有副作用"，
**而那是在事实表里写假话**。

> ### 【定】`execute` 必须是默认，而它有一个已回源码确认的后果
>
> ```
> sideEffectState === "UNKNOWN"
>   → settle-batch.ts:590   push 一个 RecoveryItem
>   → settle-outcome.ts:77  kind 降成 COMPLETED_WITH_LIMITS
> ```
>
> **不会**触发 `RECOVERY_REQUIRED`（那只在 resume 时由分支三产生），但
> **execute 档每报错一次，这个 Run 就再也拿不到 `SUCCESS`**。
> 浏览器自动化里报错很常见（元素没找到、超时），所以用户跑几次之后**应该**
> 把只读工具标成 `"read"`——不是嫌审批烦，是不想让那个降级信号变成
> **一盏永远亮着的灯**（也就等于没有灯）。

## 四条代价，一条都不许假装没有

### ① 沙箱不在

`run_shell` 有 seatbelt（阶段 3.5 决 1 坚持要真沙箱的全部价值就在这），
而 MCP 子进程是 `npx` 拉起的任意进程：能读 `.env`、能联网、能写任何地方。
这不是可以补的——沙箱一个浏览器基本等于不让它工作。

> #### 【定】审批**不是** MCP server 的安全边界（二次评审 codex P1-6）
>
> 这一段原来的结尾是「**唯一还在的闸门是审批和人**」，而它与上一句
> （进程能读 `.env`、能联网、能任意写）**不能同时成立**。回源确认：
> `connectMcpServers()` 在 `apps/cli/src/main.ts` 与
> `apps/workagent-service/src/main.ts` 里都跑在 **compose 之前** ——
> 也就是在任何 Run、任何 `ActionProposed`、任何一次审批**之前**，
> 那个进程已经以宿主用户的身份跑起来了。它可以在 initialize、
> 在通知回调、在后台定时器里自主读盘写盘外发，一次 `tools/call` 都不需要等。
>
> **准确的表述：**
>
> **写入或选择 `mcp.json` 的人，已经向那条 command 授予了宿主用户级的代码执行权。**
> 逐次审批只约束「模型请求 Atlas 发起的**某一次 tool call**」，
> 它是工具调用层的人机确认，**不是 server 的安全边界**。
>
> 这条与本仓已拍板的「命令名匹配不是安全边界」同源：一句把闸门说大了的话，
> 比没有闸门更危险 —— 它会让人以为审批那一下拦住了整个进程。

> **一处 SDK 默认就做对了的事，别改坏它**：`getDefaultEnvironment()` 是一份
> 环境变量**白名单**（POSIX 上只有 HOME / LOGNAME / PATH / SHELL / TERM / USER），
> 所以 `.env` 里的 `dashscope_api_key` 不会进子进程。这与阶段 3.5 给 `run_shell`
> 修的那条是同一件事。**不要把它换成 `process.env`**——配置里的 `environment`
> 是与它**合并**而不是替换（只传自定义变量会让子进程拿不到 PATH，`npx` 直接找不到）。

### ② 护栏 2 被绕过，而这正是它有用的原因

接上之后，`fetch_url("http://10.1.2.3")` 拒绝，`browser_navigate("http://10.1.2.3")` 放行。
**两个工具对同一件事给出相反答案。** 这必须写明是刻意的，否则下一个人会来"统一"
其中一个，而统一哪一边都错。

### ③ 登录态是 transcript 之外的隐藏状态

阶段 3.5 决 2 拒绝了持久 cwd，理由是「持久 cwd 是 transcript 之外的隐藏状态」。
浏览器 profile 里的 session 是**同一个形状，量级大得多**——跨调用、跨轮次、跨 Run。
区别在于：这次那个隐藏状态**就是用户要的东西本身**，不能拒绝，只能如实标注：
`execute` 档一律 `requiresPreFingerprint: true` ＋ 不注册 Verifier → `canObserve` 恒假 → 分支三。

> #### 【定】它比这一段原来写的更重：**不在内存里，在磁盘上**（2026-09-01 实测改写）
>
> 本文档「明确不做」那一节原来写着「不做 `--user-data-dir` 持久化」，
> 而实测（Run `run_18c20267c1a1`）证明**Playwright MCP 默认就在做**：
>
> ```
> 进程命令行：--user-data-dir=…/Library/Caches/ms-playwright-mcp/mcp-chrome-d83d3ae
>
> ~/Library/Caches/ms-playwright-mcp/
>   mcp-chrome-aa1e1b6   29M   (8-31)
>   mcp-chrome-d83d3ae   34M   (9-1)
>       Default/Cookies                 20,480 B
>       Default/Login Data              40,960 B
>       Default/Login Data For Account
> ```
>
> **「我们不做」与「它不发生」是两回事。** 不传那个参数并不能阻止服务器用它
> 自己的默认 profile —— 两个 Atlas 会话已经在盘上留下了两份共 63MB 的浏览器
> profile，里面有 Cookies 与 Login Data。
>
> 所以这条代价的准确表述是：登录态**在磁盘上、在 workspace 之外、跨 Atlas
> 重启存活，而 Atlas 既不读它也不清理它**。想清掉只能手工删那个目录。
>
> 这一条**只改表述、不加功能** —— Browser Session 身份仍然不做
> （2026-09-01 用户决定）。但把一句已经被实测证伪的话留在权威位置，
> 与 `MAX_TIMEOUT_MS`、`--yes`、`run_shell` 的 `/tmp` 承诺是同一族错误。

### ④ Atlas 的 workspace 边界对 MCP 子进程**不成立**

不是弱，是不存在。Policy 的写边界靠 **path 解析 ＋ seatbelt** 实现，而 MCP 工具的
参数 Atlas 根本不解析——`riskFacts` 里永远不会出现 `OUTSIDE_WORKSPACE`，
因为没有任何东西在解析那些参数。

（MCP 的 `roots` 是**建议性的**，服务器可以不理。v1 不发，将来发了也不得据此
声称边界回来了。）

> #### 实测清单：它具体写了什么，以及**跨 Run 累积**（2026-09-01 补）
>
> 跑完两个 Run 之后，`.workagent-workspace/` 里 Atlas 完全不知道的东西：
>
> ```
> .playwright-mcp/   5 个文件（page-*.yml 快照 ＋ console-*.log，两个 Run 的混在一起）
> image_urls.json    上一个 Run 的 browser_evaluate 结果
> all_image_urls.json          同上
> ```
>
> **两件事要分开看**：
>
> · MCP **调用本身**有 `ActionProposed` ＋ `ApprovalRequested`，人批准过 ——
>   这一点不要说成「零审批」（实施记录里那句话已纠正）；
> · 但子进程**在调用内部**写出的这些文件没有 FILE scope、没有逐文件 Artifact
>   记录、也**没有清理**。人批准的是「跑 browser_evaluate」，不是「往 workspace
>   写三个文件」。
>
> **累积是有后果的，而且已经咬过一次**：上一个 Run 留在 workspace 里的
> `images.zip` 被下一个 Run 的 `zip` 命令**追加**，产出了一个混着两个 Run 内容
> 的交付物（见 `settle-outcome.ts` 里版本链那条【定】）。
> 也就是说代价 ④ 不只是「这次看不见」，是**残留会成为下一次的输入**。

## 一处非做不可的类型改动：`EffectScope.kind` 新增 `EXTERNAL_TOOL`

审批展示**按 `scope.kind` 分派**，而 `PROCESS` 那一支是 `run_shell` 专属的
（`main.ts:262` 与 `human-channels.ts:193` 两处）：它读 `input["command"]`，并打印

```
沙箱：只能写 workspace 与本次调用的 $TMPDIR；禁止联网
```

**MCP 工具没有任何沙箱。** 复用 `PROCESS` 的后果是人在批准的那一刻看到一句
**方向相反的保证**，而命令原文那栏是 `(读不到命令原文)`。

`main.ts:259` 的注释写着「按 scope.kind 判而不是按工具名判——将来任何一个
PROCESS scope 的工具都自动获得同样的展示」。**那句话是对的，而这正是它的陷阱**：
展示按 scope 泛化，内容却按工具特化。加一个 kind 是唯一诚实的出路。

新分支打印：服务器名 ＋ 工具名 ＋ **完整入参 JSON** ＋ 一行

> 此工具由外部 MCP 服务器执行，**不在沙箱内**——Atlas 不解析它的参数，
> 也不约束它能读写什么。

**整份入参、不挑字段**：Atlas 不解析 MCP 的参数（那正是"换个 MCP 只改配置"的代价），
所以没有哪个字段能被认定为"关键字段"——挑就等于 Atlas 假装看懂了它。

理由与 `run_shell` 那段一字同源：`browser_navigate(内网URL)` 与 `browser_click(删除按钮)`
在一行 `scope.value` 里长得一模一样，**那不是审批，那是盲批**。
而这里比 `run_shell` 更要紧——沙箱不在，审批面是**这次调用**唯一还在的那道
（注意它管不到 server 进程本身，见代价 ① 里那条【定】）。

## 破依赖基线：3 → 4

引入 `@modelcontextprotocol/sdk@1.30.0`。**17 个直接依赖**（`express@5` · `hono` ·
`jose` · `ajv` · `zod` · `cors` · `express-rate-limit` · `pkce-challenge` …），

（先例是 ADR-0007 的 turndown：208K ＋ 传递依赖 8.6M，换来抓网页 66% 的 token 削减。
两次都记了数字。）

## 判据与注入实测

`verify:mcp` **17 条**，用手写的假 MCP 服务器（`fixtures/fake-mcp-server.ts`），
**不依赖 Playwright、不联网、不弹窗口**——拿真实服务器当夹具，测的就成了
"能不能接 Playwright"，而这一批要答的是"能不能接**任意** MCP"。

九条做过外部注入实测（改坏实现 → 退出码必须非 0）：
边界 12 · 默认档位 · read/execute 分流 · schema 放宽 · 分页 · isError 分流 · image 块 ·
连不上硬失败 · `tools` 段拼错工具名。

> ### ⚠️ 注入实测抓到了 D 段第一版的真实缺陷
>
> 它直接调 `handler.execute`，而夹具函数自己造好了 `normalizedInput`——
> **`validateAndNormalize` 根本不在那条路径上**（它由 `settle-batch` / `facade` 调用）。
> 把 array 分支改成无条件报错，那条判据**照样是绿的**。
>
> 与摸底考试 `read_blob.line_offset` 一字不差：判据打在下游，跨不过出事的那一跳。
> 修法是显式走两步、两步都断言。**这是"每加一条判据就做一次注入实测"
> 又一次证明自己的价值——靠读代码是看不出来的。**

`verify:all`：15 条脚本 / **183 条判据**。

## v1 明确不做

- remote / SSE / streamable-http 传输（配置保留 `type` 字段，加时不是破坏性变更）
- MCP `resources` / `prompts` / `sampling` / `roots`（`initialize` 里如实声明不支持）
- OAuth
- **image / resource 块进上下文**——`CallToolResult.content` 可以是 image 块，而
  `ToolExecutionOutcome.output` 是 `string`，与 ADR-0010 那个洞同形态。
  v1 的处置是丢掉正文但**点名说出丢了什么**（静默丢弃会让模型以为自己看到了截图）
- **接管 MCP 服务器的 profile 目录**。⚠️ 注意措辞：这里原来写的是
  「不做 `--user-data-dir` 持久化」，而实测证明 Playwright MCP **默认就在做**
  （见代价 ③ 里那段实测数据）。Atlas 不传这个参数、不读那个目录、也不清理它 ——
  但那份凭证存储**确实存在**。CLI 入口仍然建议用 `npm run ui`
  （service 常驻，MCP 进程跨 Run 存活，不必重开浏览器）
- 审批时"以后都放行"写回配置（等实测反馈说"问得太烦"再做——不为一个还没量过的问题先建机制）

## 待实测回填

v1 全程用假服务器验证，**没有跑过真实的 Playwright**。要盯四件事：

1. 有几个 Playwright 工具装配失败、卡在哪个字段（最小翻译够不够宽的实测答案）
2. 审批问了多少次、烦不烦（决定要不要做"以后都放行"）
3. 模型会不会主动用 `request_handoff` 请人登录——摸底考试 B 组的实测结论是
   模型在这个出口上**倾向零调用**。若不调，要改的是引导面措辞，
   **不能加"description 里必须出现某个词"的机械判据**（B 组已拒绝过那类判据）
4. 归档产物有没有被脱敏打花；反过来，登录后页面的 session token 有没有原样进 transcript

第 4 条对应下面这个选择。

### 为什么脱敏是 `STANDARD` 而不是"外部工具所以走最严"

先例明确：**`fetch_url` 也是 `STANDARD`**，而它返回的同样是任意外部网页正文。

`SimpleRedaction` 的 `STRICTEST` 比 `STANDARD` 多四条正则，其中一条是
`/\b[A-Za-z0-9]{32,}\b/g`（高熵串），注释自己写着"会误伤 hash 与 UUID"。
**一份现代网页的快照里到处是 32 位以上的字母数字串**（CSS class hash、data 属性、
内联 base64）。走 STRICTEST 的后果是归档产物被打成一片 `[REDACTED:high_entropy]`，
**而模型没有任何办法发现自己拿到的内容被改过**，然后把它写进交付物。

三条真凭证形态（`sk-` / `sk-ant-` / `Bearer`）在 STANDARD 档仍然生效。
残余风险：非这三种形态的 session token 会原样进 transcript。
要收紧的话加**逐服务器**的 redaction 配置项，**不要偷偷把默认改成 STRICTEST**。
