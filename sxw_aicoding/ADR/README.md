# ADR（架构决策记录）

上位基线 v0.4 §12 把「学习是项目第一目标」列为已拍板项，并要求每个主要研究问题至少产出：

> Problem / Hypothesis / Alternatives / Implementation·Prototype / Eval Evidence / ADR / Postmortem / Interview Narrative

本目录承载其中的 ADR 一环。**阶段完成不以写了多少代码判断，而以是否真正回答了该阶段的研究问题判断。**

## 命名

```
NNNN-短横线小写标题.md
```

编号连续、永不复用。被取代的 ADR 不删除，改状态为 `SUPERSEDED` 并指向新编号。

## 与其他文档的关系

| 文档 | 回答什么 |
|---|---|
| `方案讨论/…讨论进展.md` | 上位基线：目标、原则、边界。冲突时以它为准 |
| `架构设计/WorkAgent架构设计_V*.md` | 某一版的完整架构快照 |
| `方案评审/*.md` | 对某一版架构的评审意见 |
| **`ADR/*.md`** | **单个决策的取舍过程与代价**，含被否决的方案 |
| `WorkAgent调研/*.md` | 外部事实与实测证据 |

架构文档说「是什么」，ADR 说「为什么不是别的，以及代价是什么」。V03 第 30 章的 15 个决策点（D-01 ~ D-15）
拍板后，每个都应落成一条 ADR。

## 状态

- `PROPOSED`：已写出候选与倾向，未拍板
- `ACCEPTED`：已拍板，实现必须遵守
- `SUPERSEDED by NNNN`：被后续 ADR 取代
- `DEPRECATED`：不再适用，且无替代
