# WorkAgent 调研报告

> 调研时间：2026-08-20
> 背景：以腾讯 WorkBuddy 为代表的办公 WorkAgent 掀起热潮。Agent 发展脉络：Chatbot/ChatAgent → CodingAgent → Agent Loop → WorkAgent。

---

## 一、行业背景

- 2025 年 11 月，开源桌面 Agent 框架 **OpenClaw** 在 GitHub 走红，跑通"网关+Agent+技能+记忆"的桌面智能体骨架，让 Agent 从"陪聊"转向"替你在电脑上干活"，直接点燃本轮桌面办公 Agent 爆发。
- 2026 年被业界称为 **Work Agent 规模化落地元年**。中国智能体市场规模预计从 2025 年的 804 亿元增长至 2030 年的约 6968 亿元，复合增速超 50%。
- 易观数据：2026 年 6 月，国内 17 款主流桌面端 AI 原生办公智能体合计月访问量突破 6000 万次，三个月翻三倍。
- 2026 年 7-8 月，腾讯、阿里、字节密集完成产品线整合与组织调整，结束"赛马"，赛道进入体系化竞争阶段。

### 腾讯 WorkBuddy 详解

- **时间线**：2026.1.19 内部测试（2000+员工）→ 2.6 启动内测 → 3.9 正式发布 → 6.5 发布企业版。马化腾亲自督战，内部按"超级项目"推进，被视为腾讯继 QQ、微信之后的第三大战略产品。

- **核心能力**：

  - 连接器：基于 MCP 协议 + OneID 统一身份，一键接入企微、腾讯文档、腾讯会议、QQ 邮箱等 10+ 腾讯系产品，兼容飞书、钉钉

- **企业版（6.5 发布）**："从超级个体到超级团队"——7×24 云端数字员工、人机协同"项目"模式、企业管理后台（组织治理/审计/成本归集），配套 Agent Suite（腾讯文档+网盘+乐享知识库）。支持公有云/VPC/私有化交付。
- **商业模式**：订阅+积分（1 积分≈0.05 元）。个人版免费~999 元/月四档；企业版 SaaS 198 元/坐席/月、专有云 316 元/坐席/月。当前处于战略投入期，不设商业化目标。

## 三、竞争格局与组织调整

- **腾讯**（流量入口型）：QClaw 并入 WorkBuddy 统一运营；不绑死企微，打通微信/企微/QQ/飞书/钉钉全 IM，走开放生态换规模路线。
- **阿里**（企业基建型）：三款赛马产品整合为千问办公，依托钉钉 B 端深度积淀，主攻大中型企业深度流程与跨国协同。
- **字节**（技术产品型）：飞书产品团队并入豆包、GTM 团队并入火山引擎，AI 能力植入飞书底层，服务科创/互联网企业。
- 竞争本质：争夺"默认 AI 工作台"入口与**真实工作流数据**（Agent 参与文档、会议、审批的完整执行过程数据，反哺模型训练）。
- 先发优势护城河极强：Agent 需授权、绑定、学习成本，用户迁移成本远超传统 SaaS。

## 四、后续发展路线判断

1. **从"对话生成"到"自主执行"**：核心范式跃迁，竞争焦点从模型参数转向任务完成率、交付可验收性。当前最大瓶颈是"需求理解偏差"(46%) 和"产出质量不及预期"(42%)。
2. **从超级个体到超级团队**：个人提效 → 组织协同。数字员工 7×24 云端常驻、人机同项目协作、企业知识库成为 Agent 的"记忆底座"，是各家企业版主攻方向。
3. **入口化与体系化竞争**：办公智能体成为继搜索、IM 之后的新入口级产品；办公软件退居后台，沦为 Agent 的"技能包/执行引擎"。未来一年是洗牌定型关键周期。
4. **技能生态 = Agent 应用商店**：MCP 协议 + Skills 市场成为能力扩展主通道，生态规模构成护城河。
5. **多模型开放路由**：不再绑定单一大模型，Auto 智能路由按任务复杂度调度成为标配。
6. **安全合规是生死线**：沙箱隔离、权限分级、危险操作拦截、审计追溯、私有化部署/数据不出域，决定政企市场能否打开。
7. **商业化探索**：订阅+积分/Token 计费并行，企业按坐席收费；"AI FinOps"（Token 成本审计、ROI 量化）开始兴起。标准化高重复场景（行政、运营、数据汇总）先跑通，金融/制造/政务定制周期更长。
8. **数据飞轮**：Agent 参与真实工作流产生的"工作过程数据"反哺模型训练，是巨头争夺的深层战略资源。

### IDC 五大趋势（《中国智能化工作平台 In-App AI Agent 评估, 2026》）

1. AI 原生与多 Agent 协同成为主流：从"AI 插件"到"AI 原生"平台，端到端智能业务流程重塑
2. 多模态与可视化协作持续深化：接入 XR、AI 眼镜等硬件
3. 数据治理与合规成为平台基石：细粒度权限、数据驻留、审计追溯
4. AI 治理与 FinOps 兴起：Token 消耗视为财务成本，像管水电一样审计 AI 开支
5. 竞争关键从功能数量转向：能否让 Agent 真正嵌入业务流程，在可控、安全、可审计前提下规模化落地

## 五、技术储备全景

### 1. 基座模型层（大脑）

- Agent 特化能力大幅提升：工具调用可靠性、长程规划、自我纠错（如混元 Hy3 将 Agent 任务解决率从 72% 提至 90%，平均耗时缩短 34%）
- 多模态感知（截图理解/OCR/UI 元素识别）+ 超长上下文（1M token 级）+ 快慢思考融合/MoE 架构
- 模型不再是瓶颈，"模型周围的工程"才是

### 2. Agent Harness（智能体脚手架，2026 年初正式命名）

- 定义：包裹 LLM 的全部非模型基础设施——编排循环(Agent Loop)、工具注册、状态持久化、错误恢复、验证循环、安全护栏、trace/replay、成本控制
- 三个同心圆层级：提示词工程 → 上下文工程 → Harness 工程
- 实证：LangChain 仅换 harness、不动模型权重，TerminalBench 2.0 排名从 30 名开外跳到第 5
- 类比：裸 LLM 是无内存无硬盘无 I/O 的 CPU；上下文窗口是内存，外部数据库是硬盘，工具集成是设备驱动，Harness 是操作系统

### 3. 上下文工程（Context Engineering，核心胜负手）

- Karpathy 2025.6 提出："在正确时间为 Agent 提供正确信息"，覆盖并超越 Prompt/RAG
- 五大策略：Offload（转移）、Reduce（压缩）、Retrieve（检索）、Isolate（隔离）、Cache（缓存）；另有 R&D 框架（Reduce + Delegate）
- 长上下文四大失败模式：污染(Poisoning)、干扰(Distraction)、混乱(Confusion)、冲突(Clash)
- 工具输出占上下文 80%+ 体积；未优化的 Agent 约 15~20 步后崩溃；METR 数据：Agent 可处理任务长度每 7 个月翻一倍
- Deep Agents 三级压缩：结果卸载 → 输入卸载 → 摘要（FilesystemMiddleware，"算存分离"）
- Skills 采用"渐进式披露"按需加载（初始只读 name/description）
- 长任务两条路线：Cursor 走多 Agent 大规模并行协调（共享文件+lock 机制），Anthropic 走单 Agent 跨周期记忆连续性

### 4. 协议与生态标准（连接）

- **MCP**（Model Context Protocol）：工具调用事实标准。基于 JSON-RPC 2.0，stdio/Streamable HTTP 传输；Host-Client-Server 三层架构；Tools/Resources/Prompts 三大原语。生态 5000+ Server，Anthropic/OpenAI/Google 全面支持；MCP 2.0 支持多模态；2026 路线图：OAuth 2.1 鉴权、Service Discovery、Stateless。MCP Gateway 承担多租户鉴权/限流/审计/出参脱敏
- **A2A**：Agent 间通信协议（消息格式、状态同步）
- **Skills**（SKILL.md）：能力包封装标准（元数据+指令+scripts+references），WorkBuddy SkillHub 即基于此，兼容 Claude Plugin 生态
- **ACP** 等新兴协议持续涌现

### 5. 记忆系统

- 分层记忆成主流：短期（上下文窗口/KV）→ 中期（会话/事件缓冲）→ 长期（向量库+知识图谱）
- 学术前沿（NUS+人大+复旦 2025.12 综述）：token 级/参数级/潜在级三级记忆，强调"自我遗忘"与"冲突修正"
- MemGPT、RAG、KV Cache 等多种机制并存，缺乏统一理论；Agent Memory Middleware（统一读写 API/权限/激活）兴起
- 企业知识库作为数字员工的"记忆底座"，动态反哺

### 6. 执行与操控层（手脚）

- **Computer Use 路线**（截图+坐标点击）：零适配任何应用，但 Token 消耗极高、2-5 秒/步。代表：Anthropic Computer Use、OpenAI Operator
- **DOM-based Browser Agent 路线**（结构化 DOM+语义操作）：精准、Token 高效。代表：Browser-Use（Odysseys Benchmark 87.4% 完成率）、Skyvern、Playwright-MCP/CDP
- 浏览器自动化完成从"脚本驱动"（命令式）到"智能体驱动"（目标式）的范式跃迁
- **RPA + Agent 融合**：RPA 做确定性流程执行（执行者），Agent 做动态规划决策（决策者）
- 本地文件读写（授权文件夹/工作空间）、代码执行沙箱、定时任务引擎（7×24 无人值守）

### 7. 安全与治理（进企业的门槛）

- 沙箱隔离：微软 MXC 沙箱（Capability-based 策略模型）、Docker 容器化
- 工作空间目录限定（数据不出域）、危险操作拦截+二次确认、"授权信任并验证"机制
- 全链路 HTTPS 加密、企业级 IP 白名单、SSO 单点登录、组织架构同步
- 技能(Skill)分级风险判别与审计、可观测性（破解多步推理黑盒）、trace/replay
- 提示词注入防护、权限过度开放防控、高危操作保留人工确认

### 8. 多 Agent 编排

- SubAgent 分层调度：主 Agent 负责高层规划决策，子 Agent 消化海量数据，上下文隔离防污染，配合多级智能压缩降低 Token 消耗
- 层次化 ReACT（WPS 365 Hierarchical ReACT Agent：子 Agent"工具化"，多层扩展调度）
- Swarm 并行编排（Kimi Agent Swarm：复杂任务拆解为异构子问题并发执行）
- 专家团/虚拟团队模式：自主拆解任务并调度不同领域专家并行处理
- 协调机制演进：动态协调（共享文件+lock）→ 分层调度

## 六、总结

**模型提供"大脑"，Harness + 上下文工程决定"可靠性"，MCP/Skills/A2A 提供"连接"，Computer Use/RPA 提供"手脚"，沙箱与治理决定"能否进企业"**——这五层技术储备共同支撑了 WorkAgent 从 Coding Agent 向办公场景的迁移。

赛道判断：2026 年是规模化落地元年，前中期混战格局未定，未来一年是洗牌与产品定型的关键周期。胜负手在于——谁能率先实现从"个人提效"到"组织协同"的跃迁，并在可控、安全、可审计的前提下让 Agent 真正嵌入企业业务流程。
