## 一、高严重度

### F1【高】git 只读子命令表收录了写子命令——实测免审批放行，且危害场景被一轮低估

`tools/common/src/exec/command-analysis.ts:61` 的 `GIT_READONLY_SUBCOMMANDS` 包含 `config`、`branch`、`tag`、`remote`、`reflog`。以下命令两轮均实测判为 **READ → Policy ALLOW → 完全不进审批**：

```
READ | git config user.name evil              ← 写 .git/config
READ | git branch risky-new-branch             ← 建分支
READ | git tag v9.9.9                          ← 打 tag
READ | git remote add origin https://…         ← 写 .git/config
READ | git reflog expire --expire=now --all    ← 摧毁 reflog
READ | git log --output=leak.txt --all         ← 写文件
READ | git show --output=steal.txt HEAD        ← 写文件
READ | sort -o out.txt in.txt                  ← 写文件（sort 在白名单）
READ | find . -fprint /tmp/probe.txt           ← 写文件
```

危害链条（二轮加重理由）：沙箱只保证"跑不出 workspace"，而 `npm run dev -- --workspace <真实仓库>` 时 workspace 就是用户的生产仓库——`git reflog expire --all` 会在**没有任何一次提问**的情况下摧毁该仓库的全部恢复元数据。这不是"审计失真"，是**免审批的 workspace 内不可逆破坏**。锋利度排序：`reflog expire` > `config` > `remote add` > `branch` / `tag`。

附带发现：`find . -name x -exec rm -rf {} +` 落 EXECUTE **纯粹因为 `{}` 恰好是元字符**——这是偶然防御不是设计防御，将来有人以"brace 展开很少用"为由删掉 `{}` 就破防。

**建议**：① 收窄为真只读形态（`config` 仅 `--get` / `-l`，`branch` / `tag` 仅 `-l` / `--list` / 无参，`remote` 仅 `-v`，`reflog` 仅 `show` / 无参）；② 对 argv 做**写出口参数**嗅探（`--output` / `-o` / `-fprint` / `-fprintf`）落 EXECUTE；③ 给 `find -exec` 的偶然防御加注释钉死。

### F2【高】`verify:shell` E2 的 `arithmeticOk` 是恒真断言——报告 §十一声称的"修复"本身无效

`apps/cli/src/verify/shell.ts:545-560`：

```ts
const overhead = names.length * 180;        // ← overhead 本身就是用它算出来的
...
const arithmeticOk = overhead === names.length * 180;   // ← 恒真，无任何代码能使其变红
```

这正是 AGENTS.md "a green assertion that cannot fail is decoration, not a criterion" 的活体。verdict 文案写着"与 `fixedOverheadTokens` 一致"，但代码**从未调用** `fixedOverheadTokens()`（正确用法见 `verify/tools.ts:702`）。E2 真正剩下的断言只有 `names.includes("run_shell")`。

特别之处：报告 §十一把这个修复当教训记录（"已改成断言关系而非常数"），而该关系是同义反复——**教训记录里记载的修复是无效的**，若不一起改掉，教训本身会再被抄进第二个地方。

**建议**：改为 `new ToolRegistry(spec.agentSpec.toolSnapshots).fixedOverheadTokens() === names.length * 180`，或删掉算术断言、把起步价断言留给 `verify:tools` G 段。

## 二、中严重度

### F3【中高】`timeout_ms` 声称上限 600s，实际被 Runtime 步骤超时钉死在 120s——声明与实现不符，且错误码错位

- `run-shell.ts`：`MAX_TIMEOUT_MS = 600_000`，schema 描述明写"上限 600000"，工具内部 timer 按它设；
- 但 `settle-batch.ts:428`：`stepMs = snapshot.definition.timeoutPolicy.timeoutMs`（=120s），`AbortSignal.timeout(stepMs)` **先于**工具自身 timer 触发（步骤计时从 ctx 创建起算，早于工具计时起点）。

两个加重细节（二轮补）：

1. **错误码错位**：step abort → `onAbort` → `killedBy = "cancel"` → 模型收到 `TOOL_SHELL_CANCELLED`（category CANCELLED）而非 TIMEOUT——它会误判成因（"被用户取消了？"），而真实成因是文档承诺过、实际不存在的 600s 上限；
2. `settle-batch.ts:496` 的 backstop（"工具返回 ok 但步骤已超时"改判 `TOOL_TIMEOUT` 且如实保留 APPLIED——这层设计本身很好）救不了这条路径：outcome 到达时已是 ok:false。

工具描述"构建与打包本来就慢"＋"上限 600000"是对模型的承诺，实际全部命令被钉死 120s。属本仓反复猎杀的"声明与实现不符"类。**建议**：最小修法——`MAX_TIMEOUT_MS` 降到 120000 并同步描述；根治修法——timeoutPolicy 支持 per-call 覆盖。

### F4【中，二轮内核级实证并加重】沙箱读黑名单"翻译"与 read-guard 语义不等价——双向分叉，条数相等判据钉不住

一轮靠正则语义 + JS 侧推断；二轮用真实 `sandbox-exec` 对拍（探针已清理）：

| 路径 | read-guard（JS） | 沙箱（内核实测） | 分叉方向 |
|---|---|---|---|
| `.environment.md` | 放行 | **拒绝** | 沙箱更严 |
| `.environments/readme.md` | 放行 | **拒绝** | 沙箱更严 |
| `.git`（文件，如 worktree） | 拒绝 | **放行** | **沙箱更松** |

三点加重理由：① 分叉是**双向**的，宽松方向出现在安全边界那一侧，B4"条数==规则数"对两个方向都无感知；② 沙箱侧 `(regex #"/\.env")` 正是 `read-guard.ts` 里被【定】明确否决的 `startsWith(".env")` 形态（原文理由："误伤会让人去绕过护栏"）——"唯一事实源"的声明在两个实现里各说各话；③ `.git` 文件本身敏感性低（只含 gitdir 指针），但它证明**任何依赖段匹配的 deny 规则都可能存在终段绕过**——`/\.git/` 要求尾斜杠，匹配不了作为路径终段的 `.git`。将来往 `DENIED_SEGMENTS` 加新目录时这个形态会再来一遍。

**建议**：判据从"条数相等"升级为"抽样路径双侧判定一致"（对拍表可直接抄本实验）；prefix 规则改 `#"/\.env(\.|$)"` 与 basename 语义对齐。

### F5【中低，二轮精确化】`verify:shell` B5"默认禁网"判据无自诊断

断言"curl exitCode ≠ 0"。二轮复跑 `exit=6` 且本机 `pi.dev` 直连返回 200——**今天的绿是真的**（沙箱拦的是 DNS/网络，不是没网）。问题收窄为：判据本身不区分"沙箱拦住了"与"机器没网"，在离线机器 / CI 上会**空洞变绿**——按本仓自己的标准这是夹具让正确值与错误值相等。**建议**：加一行可达性预探测，不可达时显式打印"本条无判别力"。

同段 C3 的 `pgrep -f "sleep 30"` 会匹配机器上任何命令行含该串的无关进程——今日复跑未误报（"残留 sleep 进程 无"），记为环境性假红风险，建议匹配带唯一 marker 的命令串。

### F6【中】超时 / 取消时丢弃已捕获的部分 stdout/stderr

`run-shell.ts` 的 `killedBy` 分支返回 `output: ""`。一条跑了 110 秒被 120s 步骤超时杀掉的构建命令，前 110 秒的编译错误全部蒸发——模型只拿到"副作用状态未知"，看不到任何诊断线索，大概率原样重跑。`sideEffectState: "UNKNOWN"` 是对的，输出不该陪葬。这与同文件头"静默截断会让模型拿半截输出当完整结果"是同一条理由的反面：应如实上报**部分输出＋截断事实**（Claude Code 亦返回 partial output）。

### F7【中低】UTF-8 按 chunk `toString` 会拆多字节字符

`child.stdout.on("data", (b) => append("out", b.toString("utf8")))`——chunk 边界落在 CJK 字符中间时产生 U+FFFD。本仓主要使用场景就是中文输出（`grep 中文`、`echo 中文日志`）。**建议**：累积 Buffer，flush 时统一解码（或用 `StringDecoder`）。
